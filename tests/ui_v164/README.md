## 这一版踩到的坑（写下来免得下一个探针再踩）

### 1. ★★★ 六个 `renderUI` **一个都没渲染** —— 而自检全绿

第一版探针 ② 一开就是 `实际 0 行；提示原文=''`，六块全空。R 那边
`dsapp_cloudreg_table()` 返回 58 行、自检 41 条全绿，浏览器上一个字都没有。

原因是 Shiny 的 `suspendWhenHidden`：面板是**前端**切的（`display:none`），
而 `display:none` 里的 output **永远不会被计算**。更阴的是它判定"藏起来了"
的方式 —— `if (is.null(hidden)) hidden <- TRUE`：**客户端还没上报过**也算
藏起来了。所以那六块从进页面到点开面板，一次都没有被求值过，
DOM 里就是空的，而且**控制台一条错都没有**。

修法是 `outputOptions(output, <name>, suspendWhenHidden = FALSE)`
（`R/mod_files.R:2032` 有同样的用法）。自检里加了 ⑦ 钉住"六个 output 都在
那份名单里"。

### 2. ★★ `outputOptions()` **当场查名字**，查到没有就抛 —— 整页空白

第一版把那六行写在 `output$tcga_rows` **之前**，报的是
`cloudtool-tcga_rows is not in list of output objects`。这不是"那一块不画"，
是 **server 起不来**，页面上什么都没有。所以那一段现在明确写在两条
`output$*_rows` 的**下面**，并且带一段 ⚠️ 注释。

### 3. ★★ `.selectize-control` 不是 `select` 的祖先，是**兄弟**

`page.click(".selectize-control:has(#cloudtool-tcga_group)")` 永远等不到
（`has()` 匹配不到兄弟）。改成：先给那个兄弟挂个临时 id，再用真鼠标点它。
顺带，原生 `<select>` 被 selectize **清成只剩选中那一项**（不是全空），
所以"它是不是 selectize"的判据要写 `raw <= 1`，写 `== 0` 会一直红，
而报出来的「原生 option 数=1」看着完全合理。

### 4. ★★ 打完字**不能马上读**（服务端还要跑一趟）

搜「zzzz」之后 200ms 读到的是**没筛的 49 行**；400ms 时已经是 0 行 + 那句
人话。第一版直接 `rows_of()`，报的是「搜不到时没给人话」，而真相是
"读早了"。现在统一走 `wait_rows(pg, panel, pred)`：等到满足 pred 再返回，
等不到就把**最后一次**的结果原样返回，断言照红 —— 不是把红的等成绿的。

### 5. ★★ `class = "btn-primary"` 别顺手改成 `btn-outline-*`

这一版原本把那两颗「开一个对话」改成了 `btn-outline-primary btn-sm`，
功能一切正常，但**冻结在 `tests/ui_v161/probe_cloudtiles.py` 里的判据是按
`.dsapp-cloud-panel[data-panel='tcga'] .btn-primary` 找那颗主按钮的** ——
那份记录当场红两条（② 说"没有『开一个对话』按钮"、④ 30 秒超时），
报错指向的是"按钮不见了"。已改回来，并在源码那两处留了 ⚠️。

### 6. ★ 第一次开对话会弹那个「AI 怎么干活？」首选项弹窗

⑤ 点完工具跳到对话页的那一刻它盖上来，**盖的是整页**，而且 rail 之间是
前端切换、弹窗不会自己消失 —— 后面每一个 `click_tile` 都会等满 30 秒再报
`intercepts pointer events`，报错指向那块 tile。现在 `click_tile()` 一进来
先 `C.ensure_no_modal(pg)`。

## ★★★ 顺带挖出来的一个**真的会写生产库**的洞（自检的）

写这一版的两份 .md 之后，生产库的 `skills` 表里凭空多了两行内置技能
（id 25 / 26，2026-10-04 23:08:48）。查下来是**自检自己**写的：

`selftest.R` 里有一条"照 Shiny 的方式把 `app.R` 求值进子进程"的断言
（`system2(Rscript, c("-e", ...))`）。那条断言的注释写着"子进程直接继承
自检的临时 `DSAPP_DATA_ROOT`" —— **这话是错的**：

* `Rscript` 启动时会读**当前目录**那份 `.Renviron`（自检的 cwd 就是仓库根目录）；
* `.Renviron` 里的值**覆盖**继承来的同名环境变量（实测：
  在一个放着 `.Renviron` 的目录里跑 `DSAPP_DATA_ROOT=/from_env Rscript -e ...`，
  读出来的是文件里那个值）；
* 仓库那份 `.Renviron` 写的是 `DSAPP_DATA_ROOT=<仓库>/data` = **生产库**。

于是那个子进程把 `app.R` 求值进了生产数据目录：建连接 → 跑 schema →
**种内置技能**、跑启动清理（把中断的任务标失败、收 `run/` 里的中转文件、
删孤儿工作区）。V16.4 之前这些都是幂等的（技能早种过了、没东西可清），
所以这个洞一直是**静默**的；这一版新加了两份内置文档，它下一次跑就真的
插了两行进去。

**判据**（不是推理，是量的）：拿 `lsof` 盯着生产库跑一整轮自检 —— 改之前
抓到 1 个 pid（就是那个子进程，`15ur` 读写打开），改之后 0 个。

**修法**：子进程改成 `Rscript --no-environ`（一个 .Renviron 都不读）
+ `env = c(DSAPP_DATA_ROOT=<自检的临时目录>)`，并让子进程把
`dsapp_config()$data_root` **报回来**，父进程当场对账（新增一条断言 ——
把这两样去掉哪一样它都红）。

⚠️ 生产库里那两行**留着**了：它们是这一版的内置技能，线上 worker 下一次
换代本来也会按名字种进去（`dsapp_skills_seed()` 是"没有就 INSERT、body
不一样就 UPDATE"）；删掉反而是又一次对生产库的写。
