# tests/ui_v154 —— Test_V15.4 的浏览器验收（八条）

## 怎么跑

```bash
# 起一个只在 127.0.0.1:8924 上听的实例（数据目录在 /tmp 下）
bash tests/ui_v7/make_instance.sh 8924 /tmp/dsapp_v154

python3 tests/ui_v154/probe_v154.py        # 退出码 0 = 全绿
```

探针自己会拉起一个**假 LLM**（`tests/fake_llm.py`），并把这次注册的账号的
设置行 + 钥匙串都指向它，然后 `page.reload()` 让新会话从库里读回来。
换目录/端口就用 `DSAPP_TEST_URL` / `DSAPP_TEST_APP` / `DSAPP_TEST_OUT`。

> ⚠️⚠️ 起实例别绕开 `make_instance.sh` 自己 rsync：仓库根目录那份 `.Renviron`
> 的 `DSAPP_DATA_ROOT` 指的是**线上数据目录**，整个拷过去的话实例会**连着
> 生产库**启动 —— 照样能起来、照样监听端口，页面上一点异样都没有。
> 还有：`rsync -a --delete R/ <目标>/` 这种**带尾斜杠的多源**写法会把实例树铲平。
>
> ⚠️ **只有 `www/` 是刷新即变。** `R/*.R` 只在**进程启动时** source 一次，
> 改完 R 代码必须重起实例。判据：
> `ps -eo pid,lstart,cmd | grep 'runApp(port = 8924'` 的启动时刻**比改动的
> mtime 新**。`make_instance.sh` 自己会拿 `ss -ltnp` 找出旧 pid 再 `kill`
> （**不要用 `pkill -f`**，那个模式会把当前这个 shell 一起匹配上）。
>
> ★ 这一版还多一层：**开着的页面会把老 worker 钉住**，`www/` 刷了、R 没换，
> 于是"改了一半生效"。这正是用户第 1 条「更新后要重新点一次」最可能的现场。

> ⚠️⚠️ **一条出网请求都不许打到真厂商。** 探针里有两道闸：
> ① `seed_llm()` 把 base_url 同时写进**设置行和钥匙串**，再 reload；
> ② 每次发完消息断言 `fx.req_n() > 0` —— 假服务端真的收到了。真打到厂商的话
> 它一个请求都收不到，这一条会**响**。
> 没有这两道闸的话，"Key 不对"（401）和"配置没生效"长得一模一样。

> ⚠️ 跑自检/探针**别把两次后台运行写进同一个日志文件**。`> /tmp/x.log` 是
> 截断 + 各自的 fd 偏移，两份输出会交错成一份谁也读不了的日志，而且**两个
> 任务的完成通知只会告诉你"命令结束了"**（exit code 是包装 shell 的，不是
> `Rscript` 的）。一律一个运行一个文件名，跑完 `grep -ac '✗'` 数红叉。

### 每条工单的判据（都是**几何/字节/请求体/回库**，不是"看着差不多"）

1. **自愈**：先把 `users.llm_api_key` 列**真的抹掉**（前面三条 `★ 前提` 就是
   在断"钥匙串里那把还在、列确实空了"）→ `page.reload()` → **不点任何按钮**
   直接发一条 → 断言 ① 假 LLM 真收到了、② **列被补回库里**了（不是只在内存
   里兜着）、③ 补回来的密文**解得开且和原来那把是同一个**（不是写了个空壳）、
   ④ 页面上没有出现「请先到设置页填 API Key」这类要用户动手的提示。
   ⚠️ 判据必须是**能解密**，不是"行存在" —— `data_root` 一变，行还在但密文
   解不开，补回去等于把另一个坏法写进列。
2. **产物同步**：点真的 `.dsapp-code-run` 让代码在服务器上跑出文件 →
   **不切页签、不点任何东西** → 断言右栏 30 秒内出现该文件（自动），
   再点那颗手动刷新按钮断言有回执，**再点一次照样有回执**（Shiny 值没变就
   不派发，所以那颗按钮走的是 `Math.random()` 那条既有写法）。
   最后回库断任务 `status = success`（产物是**跑出来的**，不是夹具塞的）。
3. **失败卡片**（item 2 前半）：见下面那节。
4. **思考不闪**：指纹法（V15.3 那套）。给 `<pre class="dsapp-think-pre">` 盖一个
   一次性 `data-uuid`，每 200ms 取一次 → uuid **全程只有一种**、字数**只增不减**
   且至少跨两个不同值；转圈节点在；提示词节点的 uuid 全程不变（**轮换没有引起
   重画**）而 `textContent` **至少换过 2 句**，且换的句子都在内置那 12 条里
   （防止出现半截话/空串）；两格一次生成下来失效 ≤ 8 次。
5. **重发**：点用户气泡上的「重新发送」→ 断言输入框里出现**原文**、
   **没有**新消息落库（回库数 `messages` 行数）、也没有多出第二条用户气泡。
   外加"**每一条**用户气泡都有这颗按钮"（只挂最后一条是个很容易漏的写法）。
6. **围栏渲染**：一条消息里同时放 ```` ```python ```` 围栏（围栏**内**含
   `<section><h2>实际静态图</h2>` 和 `<img alt='…' src='data:image/png;base64,…'>`）
   和围栏**外**的 `<h4>` + 一张裸的 `data:` 图。断言：气泡里**没有字面的 `\n`**
   （整段塌成一行的指纹）、页面里**没有**把「实际静态图」渲染成标题的活 `<h2>`、
   那段 Python 落在 `<pre>` 里且**≥ 5 行**、那个 `<pre>` 的
   `getBoundingClientRect().height` 明显大于一行（没有被块级元素截断）、
   围栏里的标签**原样是文字**；同时围栏**外**的 `<h4>` 仍然是真元素（**没修过头**）、
   裸的 `data:` 图是活的 `<img>` 且 `naturalWidth > 0`（**图真的解码出来了**，
   不是"src 是对的"）、只留了白名单属性。
7. **后台管理**：直接改 `users.admin_scope` 再 reload，站到**两个身份**上各看一遍。
   平台视角：左栏**只有一项**「后台管理」、5 个子页签、14 张卡片一张不少且不重复
   （+ 提示词编辑器 = 15 个卡头）、每一页点过去真的切了、提示词那一格渲染出来了。
   项目视角：也**进得去**、只有 3 个子页签（没有「平台总览」）、提示词那一页
   **根本不存在**（不是藏起来）、平台专属的 8 张卡**一个都没渲染**（不是 CSS 藏）。
8. **提示词可改**：左栏列 **10 个常量段**、`value` 是常量名、**显示的是中文标签**、
   拼出来的那 2 节标着「只读」且没有 textarea → 改一节 → **回库确认**
   `prompt_overrides` 写进去的是**被改的那一节**（不是别的 key）→ 发一轮，
   断言下一个请求**出网请求体**的 system 消息里**含**改后的文本、
   而且改前那一节的原文**不再整段出现**（真的换掉了，不是叠加）→
   「恢复默认」**先问一遍**、确认后那一行被删掉（表回到空）。
   ⚠️ 开场那条 `★ 前提` 是在断"这一轮开始前表是空的" —— 上一轮跑出来的行会
   原样留在库里，"改完库里有一行"在**这一次压根没生效**时也照样成立。

## item 2 前半：这一版最值得记的一节

用户原话是「**你看下最新的『绘制国旗』任务，报错了，但是却并没有告诉用户做
操作和选择**」。查下来的现场（**不是推断，是把线上那条消息按当时的代码在 R 里
重画了一遍**）：

- 生产任务 `#132`（`failed`, `exit_code=1`，会话 `s-20260929151421-4666`，
  标题「绘制国旗」）。
- `dsapp_env_failure()` 判出来 `is_env=FALSE, kind="code_bug", self_fix=TRUE,
  label="Python 代码本身写错了", matched="TypeError:"`。
- 该用户的 `users.ui_prefs` 里 `agent_autofix = true` →
  `quiet_fail = TRUE` → 走的是**静默分支**，而那个分支整段用户可见的内容就是
  一行灰字：「**这一段没跑通，AI 已经在自动重试了 —— 你不用做什么。**」
- 于是：**没说什么坏了、没有一个可以点的东西**。用户接着打了三句
  「继续」「继续」「制作完了吗」。

改法（`R/render.R`）：

- 新纯函数 `dsapp_fail_plain(env, err)`：把 `label` 和**报错正文的最后一行**
  拼成一句（跳过 `Execution halted` / `Warning message` 这类噪音行、截断到
  160 字），得到「Python 代码本身写错了 —— TypeError: …」。
- 新 `dsapp_retry_btn(t, retry_input)`：一颗「**重试这一步**」，`onclick` 走
  `dsapp_fire(retry_input, tid)`；服务端 `observeEvent(input$task_retry)` 用
  `db_task_get()` 取回**当时那段代码**，走 `engine$start()` 重跑，并
  `manual_run(...)` 登记 —— **这一条是必须的**，否则任务跑了但结果永远
  写不回对话（写回是 `observeEvent(engine$state$running)` 那条路在读
  `manual_run()`）。
- ⚠️ **不能用 `dsapp_chat_run()`**：它第一个分支就是
  `if (identical(target$kind, "local")) dsapp_chat_run(blk)` → 「导出脚本」，
  目标是「本机」时它会**静静地变成导出**。
- ⚠️ 静默分支里**故意没有**「让 AI 分析这个报错」那颗按钮 —— 那是 V13.x 的
  既有要求（「语法错误不要交由用户解决」）。自检里有一条专门钉住这件事。
- 「重试这一步」和「让 AI 分析这个报错」在 UI 上写明区别：前者**只是把那段
  代码再跑一遍**（不过模型、不花 token），后者是**把报错填进输入框**、
  你确认后再发。两者都不替用户发出去。
- ⚠️ 静默分支那句「AI 已经在自动重试了」是**渲染那一刻**的判断，一张历史卡片
  没法自证。这恰恰是必须有那颗按钮的理由。

## 这一版新踩的坑

**1. ★★ 自检里插了新一节，结果它读的变量定义在**后面**。**
`v154_chat_raw`（item 2 后半那节定义的）被我这一节引用了，报的是
`object 'v154_chat_raw' not found`。修的时候我试图把整节往后挪，`i = 1` 时
`j = i - 1 = 0`，再往回走"跳过 `#` 和空行"的那个循环**走到负下标**、绕到文件
末尾，`rest[:-5424]` 成了空 → 整节被**追加到 `quit()` 后面**（自检照样退出，
那一节一条都没跑）。正确解法是**别挪**：在新一节里自己
`v154_retry_src <- paste(readLines("R/mod_chat.R"), collapse = "\n")`。

**2. ★★ 断「源码里不许出现某个写法」时，那个写法就写在我的注释里。**
`!grepl("dsapp_chat_run(", blk, fixed = TRUE)` 红 —— 我解释"不要用
`dsapp_chat_run()`"的那句注释把字面量带了进去（`scan-source-strip-comments`
第四次）。改成锚一条**真的语句**的形状：`"\n      dsapp_chat_run("`。

**3. ★★ `render.R` 里没有 `task_retry` 这个字面量。**
`render.R` 收到的是**参数** `retry_input`，`input$task_retry` 只出现在
`mod_chat.R`。第一版断言写在 render.R 的文本上，红得毫无道理。改成断
`dsapp_fire(retry_input, tid)` + 两个挂载点 `retry_input = ns("task_retry")`
和 `retry_input = retry_input`。

**4. ★ 中文字符串里嵌 ASCII 双引号**（`（用户要的"操作和选择"）`）——
Python 语法错误一次报三个。一律用「」。这条在 v153 的 README 里写过，
还是又踩了一次。

**5. ★ `retry_input = NULL` 时会剩下一句"孤儿提示"。**
第一版把「一直没动静的话，可以点它再跑一遍。」写死在 `.dsapp-run-ops` 里，
按钮不渲染时那句话还在，指着空气说话。改成先算 `retry_btn`，那一格和提示
**一起**受它管。

**6. ★★ `_common.py` 的 `nav` 名单里留着一个已经不存在的 value =
后面所有几何断言都量在别人的元素上。**
`htadmin` 合并掉了，但 `goto(page, "htadmin")` **不会报错** —— 它调
`dsappNav("htadmin")`，找不到那个 value 就**静静留在上一页**。
`pages` 名单和 `NAV_ZH` 两张表都清掉了它。

- 实例的 `app.log` 里可能有 `Warning: ... already running` —— 换页/重连时的
  正常噪音。
- 跑完 `/tmp/dsapp_ui_v154/` 下有一串截图（`00_register_failed.png` 只在注册
