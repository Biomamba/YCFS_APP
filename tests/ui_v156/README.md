## 这一版在修什么

用户原话：「**GPT6文献解析这个任务运行到一半，没有转圈，也没有新的提示，
就停在那了**」。

查下来的链条（**不是推断**：把那 134 条线上含围栏的 assistant 消息逐条喂进
平台的解析器跑过）：

1. 模型写代码块时，**开围栏粘在正文行尾**：
   `……首次检索预计耗时 1 分钟。```python`（而不是自己占一行）。
2. 当时的分段器要求开围栏**必须独占一行**（`^\s*````），于是这一行整行被当成
   **正文**——围栏和它后面直到闭围栏的全部代码，一个字都不进代码块。
3. `dsapp_agent_pick_block()` 拿到「回复里一个代码块都没有」→ `kind = "none"`。
4. agent 循环把 `"none"` 解读成**「模型给出了结论，这一轮到此为止」** → 循环
   正常结束：不执行、不报错、不写工具消息，**界面上连转圈都停了**（不是卡死，
   是它认为自己干完了）。现场 6 条回复都是这么消失的。

## 改了什么（四处）

| 文件 | 改法 |
|---|---|
| `R/render.R` | 新 `dsapp_fence_open()` / `dsapp_fence_close()`：开围栏**可以粘在正文后面**（只要它后面只剩一个语言标注或什么都不剩），**闭围栏必须独占一行**且反引号数 ≥ 开围栏（CommonMark 规则）。`dsapp_split_segments_raw()` 改用它 |
| `R/jobs.R` | `dsapp_parse_code_blocks()` 改成**同一套**判据（之前两个解析器各写一遍，改一个漏一个就会两处对不上） |
| `R/agent.R` | `dsapp_agent_pick_block()` 新增 `kind = "unparsed"`：回复里有 ``` 却一个块都认不出来时**不再冒充 `"none"`**；`on_llm_done` 为它加一支，回一句人话让模型重发（`a$feed_back()`） |
| `R/prompts.R` | 手动/agent 两版代码规则里都加了「围栏必须自己占一行」，配 ✅/❌ 例子 |

顺带修掉两个**顺手挖出来的真 bug**（都不是这一版引入的，但都在改动路径上）：

- `R/render.R` 的 `dsapp_md_repair_fences()`：判"这串反引号是不是粘着的围栏"
  时只问「有没有不在行内代码段里的 3+ 串」。**行中间**那一串反引号在
  CommonMark 里永远开不了围栏，被它当围栏拆到行首之后，后半句会被当成
  info string **整个吃掉**——`这一段用 ``` 包起来就行，不用给我代码。` 渲染成
  「这一段用」+ 一个语言叫「包起来就行，不用给我代码。」的**空代码块**。
  用户的原话凭空少了半句，库里和日志里一个字都不差。判据改成和
  `dsapp_fence_open()` 对齐（行尾型才算）。
- `R/files.R` 的 `dsapp_art_files_ref()`：`paste0("files:", character(0))` 给的是
  **长度 1 的 `"files:"`**（不是长度 0），拿它去填 0 行的表就是
  `replacement has 1 row, data has 0`。**文件区为空是新对话的常态**，于是右栏
  产物卡片整张渲染不出来，只剩一片红字 Error。`dsapp_art_files_ref_in()` 里
  同一个坑（那句 `%||% ""` 会先把零长度换成 `""`，守卫必须写在它**前面**）。

## 三节各管什么

| 节 | 场景 | 断言 |
|---|---|---|
| A 渲染侧（手动模式） | 假 LLM 回一条**粘着围栏**的回复 | 10 |
| C 反面 | 正文里**随口提**一个 ```（不是围栏） | 4 |
| B 循环侧（自动执行 + 本地电脑） | 对照（行首围栏）+ 实验（粘着的围栏）各跑一轮 | 6 |

**A**：代码卡**真的长出来了**（修之前是一整片正文、0 张卡）、语言标注是 Python、
代码正文里含 `glued-ok`、状态是「待执行」、卡片有**非零矩形**（隐藏元素的矩形
是全 0）、围栏前那句话**还在正文里**、气泡里**没有字面的 ```python**、composer
里那颗「确认执行」**亮着**（`pending_code()` 解析出 0 个块时整颗按钮根本不渲染）。

**C**：一句提到 ``` 的正文**不**长代码卡、那句话**原样在**（没被切掉、也没变成
代码）、没有「确认执行」可点。这一节是判据放宽的**边界**：放宽成"见到反引号就
当围栏"的话它会红。

**B**：判据是**库里的 tool 消息**（`【执行结果 · 未执行】`，只有
`a$try_submit()` 在「本地电脑」那一支才写），不是界面上那枚「第 N/M 轮」徽章
——徽章的观测窗口只有一次 HTTP 往返，漏了是常态。先跑**对照**（行首围栏）：
万一它红了，说明这一节的环境没搭对，而不是"粘着的那种没被执行"。

## 这一版新踩的坑

**1. ★★ 探针的红有三条是探针自己的毛病，不是产品的。**
（a）`A2` 断言语言标注 = `"Python"`，读到的却是 `"PYTHON"` ——
`.dsapp-code-lang` 的 CSS 有 `text-transform: uppercase`，`innerText` 拿的是
**渲染后**的值。改成不区分大小写比。
（b）`C1` 断言"0 张卡"却读到 1 张 —— `cards_info()` 是**整页**扫的，A 节那张卡
还在 DOM 里。改成只看**最后一条 assistant 气泡**里的卡。
（c）`C2` 读到「这一段用」——**这一条是真的，不是探针的**（见下）。

**2. ★★★ `C2` 的那半句话是真 bug，别急着判成探针抖动。**
一开始的推理是"库里那句是完整的、`dsapp_md_html()` 渲染出来也是完整的，所以是
探针读早了"。补了轮询（`last_assistant_text(page, until=…)`，等到它出现或连续
两次读到一样）之后**照样红**——这才去把浏览器的 DOM dump 出来看，看到的是
`<p>这一段用</p>` + `<pre><code class="language-包起来就行，不用给我代码。">`。
**"库里对、函数对"不等于"界面上对"**：中间还隔着 `dsapp_md_repair_fences()`
这一道按行改文本的处理。

**3. ★★ 判据要有"劲"，得拿已知会红的东西先捅一下。**
写"渲染后正文有没有被吃掉"的扫描时，第一版把**围栏里的代码行**也算进去了
（那些行本来就被抽成代码卡、这一轮根本没渲染），于是每条消息都"丢"一大片
——10063 处，两个版本一模一样。**两个版本给出同一个数**就是判据没劲的信号。
改成只看正文行（围栏外）之后两个版本都是 0，再单独拿那句已知会丢的话捅一下：
归档版 `FALSE`、当前版 `TRUE`，这才证明判据扫得动。

**4. ★★ 断"源码里不许出现某个写法"时，那个写法又写在我的注释里。**
`!grepl("sprintf(", blk, fixed = TRUE)` 红——我解释"不要多塞参数"的那句注释里
就原样写着 `sprintf(fmt, blk$lang)`。**第四次**踩了。自检那一段现在会先
`strip_comments()` 再断。

**5. ★★ "自检绿了"和"空表这条路跑得过去"是两件事。**
`chk("空表那条路也带 coord 列")` 当时断的是**源码文本**
（`grepl("df$coord <- character(0)")`），空表真跑一遍的那条路没人验——
于是 `paste0` 那个零长度坑全绿着漏了过去。新加的断言一律**调用真函数**。

**6. ★ 登录页和注册页的 input id 不是一套。**
登录是 `#welcome-login_email` / `#welcome-login_password`，注册才是
`#welcome-email` / `#welcome-password`。`relogin()` 里那个 fallback 只认注册那套
——cookie 还在时走不到它，所以一直没暴露；真退到登录页就必然卡满 180 秒，
报「reload 之后回不到主界面」，看着像应用坏了。两套都认了。

**7. ★ 账号口令是**注册那一刻**的时间戳拼的**（`Test-<TAG>-pw`，`TAG` 在
`_common.py` import 时生成）。事后想用另一个脚本登进去看那条消息，口令已经
猜不出来了 —— 要 dump 就**新注册一个**再把同一句话喂进去。

## ★★★ E 节折行：判据是怎么才有牙的

item 3 用户的原话是「正在返回信息的小框现在也会频繁的闪」。第一版判据是
**把窗口收窄逼它折行**——两版给出同一个数，**白送的绿**。

实测（`/tmp/probe_v156b_k.log`）才发现原因：`.dsapp-quip` 是**按内容收缩**的
flex item，视口从 1440 一路收到 320，量到的宽度都是 126~154 px —— 就是它自己
那句话的宽度。窗口再窄它也只是跟着缩，**永远量不到溢出**。真实提示词里
最长的那句（13 个汉字 ≈ 177 px）在这种布局下永远不会折。

改成**从内容这头压**：往活着的那个节点里灌一句 43 字（≈ 602 px）的
`LONG_QUIP`，420 px 的视口必然装不下。

> ⚠️ `E5` 是**前提**不是断言：必须验到「这句话真的装不下」
> （`nat > avail`，canvas 按这一格自己的字体量自然宽）。搭不起来的观测窗口
> **直接报红**，E6/E7 记作未验证——**不许当绿**。
>
> ⚠️ 别拿 `scrollWidth - clientWidth`（溢出）当「装不下」的判据，**那是反的**：
> 溢出 > 0 恰恰是 `nowrap` **在**干活的样子（一行 + ellipsis 裁掉）；
> 真折行了溢出反而变成 0。第一版就是这么写反的。

**两侧都量过**（这才是判据有牙的证据）：

| | 真实提示词（视口 420） | 灌进 43 字之后 | E6/E7/E8 |
|---|---|---|---|
| **正常 CSS** | 宽 94~276、高 **17.0~17.0**、框高 **69.0~69.0** | 17.0 px（1.00 行），框高 69.0 → **69.0** | ✓✓✓ |
| **删掉 nowrap**（已知会红） | 宽 94~276、高 **17.0~51.0**、框高 **69.0~103.0** | 51.0 px（3.00 行），框高 69.0 → **103.0** | ✗✗✗ |

坏版本那次是 **38/41，红的正好是 E6/E7/E8 三条，没有连坐**——判据指哪打哪。
日志：`/tmp/probe_v156b_final2.log`（41/41）、`/tmp/probe_v156b_mut_css4.log`（38/41）。

`E7` 的基准取的是**真实提示词里最矮的那次框高**（= 一行时的高度），
**不是**「灌之前那一句的框高」——坏版本里那一句本身可能已经在折行了，
拿它当基准会碰巧绿。`E8` 用的是**平台自己的**提示词（不是灌进去的）：
坏版本里框高在 69↔103 之间一句一跳，那正是用户说的「闪」。

## F 节：回答框（item 12）

`F3` 验它是**同一个节点**（打了记号，重画之后记号还在 = 不是 `renderUI` 画的），
`F5` 验用户敲了一半的草稿**没被冲掉**（服务端重画时如果读了 tick 就会冲掉），
`F7` 验回车**真的把那句话发出去了**——**读库**，不是只看界面
（限流/必填的拒绝长得和「渲染坏了」一模一样，光看界面分不开）。

## G 节：预览图（item 9 + 15）

`G3` 要求地址带 `v=<mtime>`（不带 = 文件被覆盖写之后浏览器还拿缓存），
`G4` 要求 `naturalWidth > 0`（**真的加载出来了**，不是一张碎图），
`G5` 要求加载完之后转圈被收掉。`G7` 验坏图**自己重试**且每次带 `_r=`
（不带 = 重试拿的还是同一份坏响应），`G8` 验重试到头（3 次）之后**画成破图
而不是无限转**——用户要的是「加载的时候转圈」，不是「永远转圈」。

## 这一版探针自己踩的坑

**1. ★★★ 探针"空白页"卡死 6 次，根因是 `goto` 之后 cookie 还在。**
第 1 次进主界面失败时，服务端**往往已经把账号建出来了**（注册是先写库再回执），
于是 cookie 落进了 context，第 2 次 `goto` **直接进主界面**——
`.dsapp-auth` 永远不出现，`wait_awake` 报「等了 150 秒还是空白页」，
**而页面根本不是白的**。
修法：**每次重试换一个全新的 context**（`_new_ctx(browser)`），进之前先看
`.dsapp-shell` 在不在（在 = cookie 生效了，直接就进主界面）。
另外 `page.wait_for_timeout()` 在 `ctx.close()` 之后调用会抛 `TargetClosedError`
**把整个 run 炸掉**，且它在 try 外面——换成 `time.sleep()`。

顺带把登录后那一跳的上限从 90 秒放到 **180 秒**（`DSAPP_TEST_BOOT_SEC`，
`_common.py`）。正常只要 **4.7 秒**（`/tmp/dsapp_enter_timing.py` 实测），
但机器被挤到 load average 17 的时候能拖过 90 秒——而报出来的还是
「页面文字 0 字」，看着像注册坏了。**慢**和**坏**要分得开。

**2. ★★ `make_instance.sh` 会连 `www/` 一起重新 rsync。**
所以「往实例里塞一个坏 CSS 看探针红不红」这种实验，会被探针自己触发的重启
**擦掉**。做法改成：**先手动重启实例，再改，再跑**——这样探针第 1 次就进去了，
不会触发重启。实验做完 `cp` 回仓库那份，`diff -q` 确认干净。

**3. ★ 常量分隔符是 ASCII 31（0x1F），不是 0x01。**
`DSAPP_THINK_QUIP_SEP`，`app.js` 里读的是 `String.fromCharCode(31)`。
我先写成了 0x01（一个**控制字符**，编辑器里看不见），结果「最长的那句提示词」
量出 1643.7 px / 只有 1 项——因为整个提示词表**根本没被切开**。
`Edit` 工具匹配不到那一行（控制字符），最后是用 Python 的 `io` 重写的。

**4. ★★ `rsync --exclude=PATTERN` 是不锚定的。**
`--exclude=mod_chat.R` 把 `R/mod_chat.R` **也一起排除掉了**，
归档 diff 里那个文件凭空少了 +180/-4 行。要只匹配传输根目录那个：
`--exclude=/mod_chat.R`。

**5. ★ 别用 `send()` 去测流式期间的东西。**
`send()` 一等等到整轮结束，而小框/提示语**只在生成期间存在**，轮次一结束它
就没了。E 节折行那一段是手动 `fill` + `click` + `wait_for_timeout(2600)`。
