# err_guard：observe 里一个错，会不会把用户的会话弄死

V15.6 item 4 的最小复现。用户报的是：

> 经常运行一半显示与服务器之间断连的弹窗，看一下是不是 APP 写的有 bug。
> 似乎是 app 在请求其它网站失败时，跟客户端也会失联

**是 APP 的 bug，但和"请求其它网站失败"无关。** 真相：

`observe` / `observeEvent` / 定时器里抛出**没人接**的错误时，Shiny 的处理是
`session$unhandledError(e, close = TRUE)` —— 把**这个会话整个关掉**。会话一关：

* 它名下的定时器全被清掉（`invalidateLater` 注册时挂了 onEnded 清理，心跳也在内）
* 前端的 socket 断开 → `www/app.js` 弹「与服务器的连接断了」
* 此后点什么都没反应，直到刷新

而 R 进程活得好好的，日志里只有一条 Warning —— 从服务端看，完全不像"用户整页死了"。
**"运行一半"是因为那些轮询（任务进度、引擎)只在跑任务的时候才活跃**：它们中间任何一个
抛错，用户就会在那一刻掉线。

## 怎么跑

```bash
bash tests/err_guard/run.sh 8971 render          # 渲染炸弹（对照组）
bash tests/err_guard/run.sh 8972 observe 0       # observe 炸弹，不装守卫
bash tests/err_guard/run.sh 8973 observe 1       # 同一颗炸弹，装上守卫
```

第三个参数是守卫开关（0/1）。脚本会起应用、开一个页面、在第 6 秒引爆炸弹，
然后按日志下结论。日志写在 `/tmp/dsapp_err_guard_<端口>_<时刻>.log`（**每次运行
一份**：两次运行写同一个日志会交错成垃圾，而交错出来的日志看着完全像是真的）。

## 2026-09-30 的实测结果

| 场景 | socket | 心跳（25 秒里） | 页面上的点击 |
|---|---|---|---|
| 炸弹在 `renderText` 里 | 连着 | 23 跳 | 收到 |
| 炸弹在 `observe` 里，**不装守卫** | **断开** | **7 跳（停在第 6 秒）** | **收不到** |
| 炸弹在 `observe` 里，**装守卫** | 连着 | 23 跳 | 收到 |

炸弹放在渲染函数里时 Shiny 自己会兜住（画成一张报错卡片，页面照常），
**只有 observe 这条路会把会话带走** —— 这就是为什么"某个图表没出来"从来不是
用户报的那个问题，而"整页失联"才是。

线上真实应用里的 A/B（同一颗炸弹，只切守卫开关）也做过一遍，结论一致：
不装守卫时 `dsappLastPing` 冻住、`shiny:disconnected` 到达、断连遮罩出现、
点击超时；装上之后四项全绿。

## 修法

`R/errhand.R` 的 `dsapp_err_soften_session()`，由 `app.R` 的 `server()` **第一行**
调用：把这个会话的 `unhandledError` 换成"照原样走一遍、但 close 一律传 FALSE"。
错误照进 `data/logs/app_error.log`、回调照调，只是不再关会话 —— 坏掉的是那一个
输出，不是整个应用。

## 这个测试的边界（别把它当成万能的）

* 它验的是**这一条**错误路径（observe 里的软错误）。别的冻结方式（R 进程被冻、
  死锁、磁盘满）不在这里，那些由心跳 + 前端遮罩负责报出来。
* `run.sh` 末尾 `kill` 进程也会触发 `onEnded`，所以判据**不能**看 onEnded 有没有
  触发 —— 脚本用的是"心跳跳数 + 点击有没有收到"。
