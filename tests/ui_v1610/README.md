# tests/ui_v1610 —— 浏览器验收（Test_V16.10）

V16.10 是两件事，都是用户原话里的：

> 「言出法随的文件页面和真正的文件管理页面文件不同步，那意味着你写了两套文件
> 展示系统，这是大大的浪费，请同步，并且支持在演出法随的文件展示中一键打包
> 下载」

1. **两个页面的展示字段收口**（同一个 `dsapp_files_rows()`），两个页面各自的
   形态保留；
2. **对话页加上「整层一键打包」**，超过同步上限（2 GB）时转后台子进程，界面上
   有 disabled + 「正在打包…（已 N 秒）」进度。

四段：A / B 全在**对话页**上量；C 是**跨页比对**（同一个目录在文件页那张表上
必须也是「📁 + 大小写 —」）；D 是**文件页那侧的转后台**（同一份勾选、同一个
`dsapp_zip_build` 子进程）。用户报的"两套展示系统"另一半就在 C、D 里。

## 怎么跑

```bash
bash tests/ui_v7/make_instance.sh 8980 /tmp/dsapp_v1610a
bash tests/ui_v1610/make_bg_instance.sh          # 第二个实例，8981，常数改小
python3 tests/ui_v1610/probe_filezip.py
```

退出码 0 = 全绿。数据目录 `/tmp/dsapp_v1610a/data`（+ `/tmp/dsapp_v1610b/data`），
截图 `/tmp/dsapp_ui_v1610`。

另有两层（缺一层就会出现本仓记过多次的「自检全绿 ≠ 功能被验过」）：

```bash
Rscript --no-environ tests/v1610_filesui.R .     # A1–A8，真行为 + 盘上核对
Rscript --no-environ selftest.R                  # 静态约定（V16.10 那一节）
```

> ⚠️ 起实例**一律走 `make_instance.sh` / `make_bg_instance.sh`**。仓库根那份
> `.Renviron` 会把一个 /tmp 实例**接到生产库**上，全程不报错、界面无异常。
>
> ⚠️ 这个实例是一个 `shiny::runApp` **单进程**，所以「R 代码只在 worker 换代时
> 生效」在这里的形态是**整个进程重启**才生效。改完 `R/*.R` 必须重跑一次
> `make_instance.sh`（它会先 kill 掉旧实例）。只 `page.reload()` 不够。
>
> ⚠️ 端口 8980 / 8981：8979 是 V16.9、8978 是 V16.8 的实例，都可能还挂着
> （收尾要拿老探针在上一版上跑对照）。探针里那条**页脚版本号**断言就是兜底的
> —— 连错实例时它比"某个选择器找不到"先红，而且报的是真正的原因。
>
> `_common.py` 是从 `tests/ui_v168/` 抄的副本（不是 import）—— 本仓老规矩：
> 这些脚本要能在「把仓库拷到 /tmp 单独跑」的场景里工作。抄的时候默认值
> （8980 / 8981 / dsapp_v1610a / dsapp_ui_v1610）已经改过，和上面那条命令一套。

## ★★ 为什么非要**两个实例**

`DSAPP_ZIP_MAX` 是应用**启动时**读进去的常数（`R/files.R:2612`），一个 R 进程
里改不了。而两条路都得在浏览器里验：

| 实例 | 端口 | 常数 | 走哪条路 |
|---|---|---|---|
| A | 8980 | 原样（2 GB） | **同步打包** —— 绝大多数用户走的就是它 |
| B | 8981 | 改成 8 字节 | **超限 → 转后台** |

* 只留 B 的话，"正常下载"这条路一次都没被浏览器验过（而它是主路径）；
* 只留 A 的话，转后台那条永远走不到（真实场景要 2 GB 的包）；
* B 的阈值必须**小于夹具里最小的那一次勾选**（整层 74 字节；D 段只勾两个
  已发布的文件 = 18 字节）。取 32 的话整层过得去、D 段够不着 —— 实例 B 会
  安安静静地走同步那条路，而探针报的是「按钮一直没变 disabled」，指向 UI，
  不指向这个阈值。**8** 是让两条都真的超限的那个数。

`make_bg_instance.sh` 里那段"**不能再跑一遍 `make_instance.sh`**"的注释要留着：
那个脚本会 `cp -a` 覆盖 `R/`，把补丁擦掉，而症状是"后台那条路测不出来"。

第二个实例那边要临时改 `_common` 的 `C.URL` / `C.DATA_ROOT`（`enter_app` /
`seed_or_die` 读的是**模块级**全局），用完还原 —— 见 `seed_and_open()`。

## ★★ 夹具必须**两个根都有东西**

`seed_zip.R` 种 5 个文件，其中 **2 个真走一遍 `dsapp_sync_artifacts()`** 进文件
区、**3 个留在工作区**（还没同步）：

```
这一层（对话文件夹根）：
  files:…/analysis.R            ← 文件区（带前缀）
  files:…/sessionInfo.txt       ← 文件区（带前缀）
  差异基因 表.csv                ← 工作区独有（不带前缀）
  volcano plot.png              ← 工作区独有
  README.txt                    ← 工作区独有
  results/                      ← 工作区独有（目录行）
```

**这正是 `dsapp_zip_plan_multi()` 存在的唯一理由**（单根的 `dsapp_zip_plan()`
喂两组坐标进去会**静默丢掉一组**）。全都同步过去的话这道题就退化成单根了，
而单根那条路文件页已经用了几个月 —— 验了等于没验。

⚠️ 名字里**故意带中文和空格**（`差异基因 表.csv` / `hub genes.png`）：
`dsapp_safe_name()` 那条下载名清洗的路要真的走一遍。上一版归档里文件名全是
有序 ASCII，那条断言从没跑过。

期望：根这一层 **6 行**（卡片本来就截断到 8 行，6 ≤ 8 所以"按钮上的 N == 卡片
行数"这条才问得动）；包里 **7 条真文件**（2 + 3 + `results/figures/` 下 2）。

## 这道题为什么非得上浏览器

R 那一侧的 A1–A8（52 条，含**真起子进程**跨进程打包）已经把"函数对不对、盘上
有没有"验穿了。下面这几条它一条都验不到：

* 那颗按钮**真的画出来了**，而且文案里的 N **真的等于**卡片列出来的行数。
  两个数**没有任何办法从界面上核对**（卡片截断到 8 行），算错一个是"看起来
  完全正常"的那种错。
* 点一下**真的下下来一个包**，而且包里**两个根的东西都在**。"点按钮 →
  服务端算计划 → 藏着的 `downloadLink` → `clickWhenReady` 补点击 → 浏览器
  落盘"这一整条链路它一个字都碰不到，而三件套（`output$x` 里的
  `downloadLink` + `sendCustomMessage` + `outputOptions(suspendWhenHidden=FALSE)`）
  少任何一件都是**静默**失效：空 href 一点就导航回首页，用户拿到一个 HTML。
* ★★ 超限那条：按钮**真的**变 disabled、真的出现「正在打包…」、跑完**真的**
  变回可点、然后**真的**开始下载。`disabled` 和进度文案都是 `renderUI` 里算
  出来的，静态扫源码看不出它们有没有生效 —— 而失效的形态恰恰是"点了没反应"
  或者"按钮永远转着"。
* **同一个量在点之前先量一遍**（那时是旧的），这样"按钮在"和"按钮跟着状态变"
  是同一个视图里的前后两帧，不是一个只测了结果、永远绿的量。
* ★★ C 段那条**跨页比对**。A/B 两段即使全绿，也证明不了"两个页面是一个说法"
  —— 只要两处**各自写死**成一样的字符串就照样全绿。真正能分出"收口了"和
  "碰巧长得像"的，是**同一个目录对象在两个页面上量到的字符串**。所以 C 段
  接在 A 段**同一个页面、同一个账号、同一份种子**上跑，不另起一个账号。
  ⚠️ 反面那条（"里面文件行的大小是真数"）是**必须**的：只断言"根上那个目录
  写 —"的话，一个"整张表的大小都没算"的坏实现照样全绿，而那种坏法用户一眼
  能看见（每个文件都显示 —）。
* ★★ D 段：文件页那条路 R 侧验不到的是**接线** —— 勾选有没有真的喂进
  `dsapp_zip_plan_multi()`、`output$tbl_tools` 那颗按钮会不会跟着 `zip_job()`
  变 disabled（它读 `zip_job()` 的那句**必须**是普通读、不能 `isolate`，和
  `zip_start_bg()` 里那句写反了是**有意**的）、`output$download` 拿的是不是
  `job$dst`。三条坏掉的样子都是"点了没反应"。

## 四个"看起来像通过"的坑（都写进代码注释了）

* **`a.dsapp-file-link` 会多数出缩略图**。缩略图下面那行文件名也是
  `… dsapp-file-link`（`R/mod_chat.R:5486`），而夹具里**就有图**。行要认
  `a.small.dsapp-file-link`；顺带把"行 + 缩略图 == 全部链接"也断言上，
  选择器漂了立刻看得见。
* **忙的时候点不动那颗按钮**（它就是 disabled），而 `locator.click()` 会一直
  等到超时、报"元素不可点"，看着像按钮坏了。所以"连点两下"那个竞态是用
  `Shiny.setInputValue('chat-art_zip', …)` **直接派发 input** 模拟的 ——
  那正是"第二下在 renderUI 更新之前到达"的形状。
* **状态翻转要熬过时间常数**。`invalidateLater(1000)` 决定 busy 态至少存在
  1 秒，所以 100 ms 一轮抓是稳的；而"变回可点"必须在**下载落地之后**再量
  （解锁和 `clickWhenReady` 是同一条 observer 里先后发生的）。
* **"变回可点"必须先要求"刚才真的忙过"**。不加这个前提的话它在**旧代码上也
  会绿** —— 那些版本从头到尾就没 disable 过。本仓老账：变异测试的变异可能是
  空转的。

## 别的

* 进对话页先 `C.ensure_no_modal(pg)`：新账号第一次开对话会弹「AI 怎么干活？」，
  它盖在整页上，**所有** click 都报 `intercepts pointer events`，报错指向按钮
  本身。
* 种完库要 `pg.reload()`：会话列表是登录那一刻拉的一次，而夹具是**另一个
  进程**写的。
* `seed_zip.R` 一律 `Rscript --no-environ`，data_root 只由命令行给 —— 仓库根
  那份 `.Renviron` 指着生产库，而 Rscript 读 **cwd** 的 `.Renviron` 并**盖掉**
  继承的环境变量（本仓为此在生产库里种过东西）。
