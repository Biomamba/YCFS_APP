# tests/ui_v153 —— Test_V15.3 的浏览器验收（六条界面/渲染问题）

## 怎么跑

```bash
# 起一个只在 127.0.0.1:8923 上听的实例（数据目录在 /tmp 下）
bash tests/ui_v7/make_instance.sh 8923 /tmp/dsapp_v153

python3 tests/ui_v153/probe_v153.py        # 退出码 0 = 全绿；55 条断言
```

探针自己会拉起一个**假 LLM**（`tests/fake_llm.py`），并把这次注册的账号的
设置行 + 钥匙串都指向它，然后 `page.reload()` 让新会话从库里读回来。
换目录/端口就用 `DSAPP_TEST_URL` / `DSAPP_TEST_APP` / `DSAPP_TEST_OUT`。

> ⚠️⚠️ 起实例别绕开 `make_instance.sh` 自己 rsync：仓库根目录那份 `.Renviron`
> 的 `DSAPP_DATA_ROOT` 指的是**线上数据目录**，整个拷过去的话实例会**连着
> 生产库**启动 —— 照样能起来、照样监听端口，页面上一点异样都没有。
> 还有：`rsync -a --delete R/ <目标>/` 这种**带尾斜杠的多源**写法会把实例树铲平。
>
> ⚠️ 实例里 `R/*.R` 只在**进程启动时** source 一次。改完 R 代码必须重起实例，
> 判据是 `ps -eo pid,lstart,cmd | grep SockJSAdapter` 比改动时间新。

> ⚠️⚠️ **一条出网请求都不许打到真厂商。** 探针里有两道闸：
> ① `seed_llm()` 把 base_url 同时写进**设置行和钥匙串**，再 reload；
> ② 每次发完消息断言 `fx.req_n() > 0` —— 假服务端真的收到了。真打到厂商的话
> 它一个请求都收不到，这一条会**响**，而且 item 6 里那条会直接 `sys.exit`。
> 没有这两道闸的话，"Key 不对"（401）和"配置没生效"长得一模一样
> —— `v153_maxtok_fix.R` 就为这个白查了一轮。

## 这一版管六件工单

| 工单 | 一句话 | 断言 |
|---|---|---|
| item 1 | 论坛页左侧要有留白 | 5 |
| item 2 | 400 报错上亮一颗「直接帮我设置」，点了自动改配置 | 16 |
| item 3 | 思考过程往外流，**不要闪** | 7 |
| item 4 | 确认执行 / 补点建议 / 停止三颗按钮挪进正在执行的会话里 | 10 |
| item 5 | 选技能时能查看技能内容 | 10 |
| item 6 | md 的 HTML 标签要渲染、图片要显示 | 7 |

### 每条工单的判据（都是**几何/字节/请求体**，不是"看着差不多"）

1. **论坛左留白**：量论坛页那个**可见**文字元素的 `x`，和设置页 `card-body`
   里首个文字元素的 `x`，两者对齐（±2px）。实测 280.0 vs 281.0。
   外加"留白真的存在"（不是两边都顶到边沿）和"论坛页挂着 `.dsapp-page-flush`"。
2. **一键修**：真 HTTP 400 → 错误气泡里有原文 → `#chat-maxtok_fix` 可见 →
   点下去库里多一行 `model_param_limits` → **模型服务页的数字和它的 `max`
   属性一起变了** → **下一次出网请求体里的 `max_tokens` 就是那个数**。
   中间那条只有出网请求体证得了（`fx.req_body()`），后面那条只有真 DOM 证得了。
3. **思考不闪**：指纹法。给 `<pre class="dsapp-think-pre">` 盖一个一次性
   `data-uuid`，每 200ms 取一次 → 断言 uuid **全程只有一种**（节点没被换掉）、
   字数**只增不减**、至少跨两个不同字数。外加 `shiny:outputinvalidated`
   数 `thinking_box`（一次生成 ≤ 6 次）。
4. **三颗按钮**：任意一拍 `.dsapp-output-bar` 都不存在；可见的
   `.dsapp-run-actions` **从不超过一处**、可见的停止按钮**从不超过一颗**；
   空闲时一颗都不亮。
5. **技能查看**：点「查看」→ 弹窗里出现**渲染后**的正文（有真 `<h1>/<li>`、
   看不到 `##` 和 `**`）；**同一行的勾选框**和**整个弹窗的勾选集合**
   点前点后逐字相同。
6. **md**：一条消息里同时放 `<h4>` + 工作区里的真 PNG + `![](../../etc/passwd)`。
   断言真有 `<h4>` 元素、**没有** `<h4>` 字面量、图的 `naturalWidth > 0`
   （**图真的解码出来了**，不是"src 是对的"）、整页没有任何 `<img>` 指向
   `/etc/`。

## 八个坑（都踩过，按踩的先后）

**1. ★★ 新账号第一次开对话会弹「AI 怎么干活？」，它盖住整页。**
有它在，`page.click("#chat-send")` 会以
`<div id="shiny-modal"> intercepts pointer events` 超时 —— **报错指向的是
"发送按钮点不动"**，和真正的原因（一个首次运行的首选项弹窗）隔着十万八千里。
对策：`ensure_no_modal()`，认 `#chat-agent_pref_manual` 那颗按钮点掉它。
⚠️ 它**只处理这一个已知的弹窗**，遇到别的会 `sys.exit` 并把弹窗文字打出来
—— 不要顺手按 Escape，那会把自己正在测的东西一起关掉（item 5 就开着弹窗）。

**2. ★★ `page.reload()` 之后 cookie 直接进主界面，登录页一帧都不出现。**
`wait_awake()` 只认 `.dsapp-auth`，拿它等 reload 等于等一个永远不会来的东西：
报出来的是「reload 之后 120 秒还是空白页」，而屏幕上其实早就是主界面了
（症状指向"服务端卡死"）。对策：`relogin()` 等的是"两个可能里先到的那个"。

**3. ★★ 发一条消息**不**建工作区。**
`dsapp_ws_dir(create = TRUE)` 只在跑任务（`executor.R`）或传文件（`files.R`）
时才走到。第一版在 `workspaces/` 底下挑最新目录，报的是"第一条消息没建出会话"
—— 会话其实建得好好的（`sessions` 表里有）。对策：`newest_ws()` 从库里读
`sessions.id`，按 `dsapp_ws_name()` 那条规则**算**出目录名再自己建。

**4. ★★ 图"显示出来了"要看 `naturalWidth`，不是看 `src`。**
`<img src>` 是对的但图裂了，在 DOM 上和"图好好的"长得一模一样（V14 那个内联
丢属性的 bug 连"图裂了没有"都躲过去了）。夹具写的是一张 74 字节的**真 PNG**
（`struct` + `zlib` 手搓，不依赖 Pillow）—— 换个假文件名的 GIF 会让
`naturalWidth` 是 0。

**5. ★★ 快照式探针量不到"闪"。**
要是整个回复在一个 200ms 轮询周期内就吐完了，一次采样都取不到，"指纹全程不变"
会**因为压根没采样而通过**（假绿）。对策：`fake_llm.py` 加了 `slow.json`
慢放模式（按 SSE 事件块一块一块写、每块之间 sleep），本次用 0.35s。

**6. ★★ 「点了还没渲染出来」和「按钮重复」是两回事。**
`#chat-send` 的置灰是 app.js **乐观地**先做的，而动作条要等服务端渲染出那条
流式气泡（`dsapp_chat_send` 里查库+拼上下文+起 callr 子进程）。这一段里
busy 已经是 TRUE 而气泡还没画出来。断言写成 `== 1` 的话量到的是这段延迟，
报出来的是"停止按钮重复" —— 指向完全错误的地方。对策：判据是
**任何一拍都不超过一颗**（出现 2 才是回归），外加"它真的出现过"
（否则前一条会因为一次都没采到而空过）。实测 3/7 拍在那个窗口里。

**7. ★★ 学到的上限记在**出网请求里那个模型名**底下，不是探针种进去那个。**
探针种的是 `fake-model`，而应用会把它换成厂商下拉里那个
（`dsapp_vendor_models()` 拿不到 `/models` 列表时退回 `fallback_models`，
`fake-model` 不在里面）—— 库里记的是 **`deepseek-flash`**。第一版照着
"我种了什么"去查，报的是"库里没有那一行"，而那一行好好地在，只是键不一样。
对策：按**值**查（见下一条），模型名留给"和出网请求对一次"。

**8. ★★ `model_param_limits` 是全局表，没有 `user_id`。**
按 `(厂商, 模型, 参数)` 存，上一轮跑出来的行会原样留在库里；R worker 没换代的话
进程内存里也还留着它。固定用一个数（比如 65536）的话，"点完之后库里有一行"
在**这一次点按钮根本没生效**时也照样成立。对策：每轮从 `20005~29999` 里挑一个
库里没用过的数，并且**点之前先断言库里没有这个值**。

### 还有两个小的

- **`#model-max_tokens` 不是 `#max_tokens`**：模型模块的命名空间是 `"model"`
  （`app.R` 的 `mod_model_ui("model")`）。写成 `#max_tokens` 时 `count` 永远是 0，
  报出来的是"控件读不到"，看着像"配置没应用上"。而且要 `wait_for_selector`
  等它渲染（`ui_v1314` 那条探针等的就是它）。
- **勾选框要**按行**读**：技能是按名字排的，探针种进去的那条不一定在第一行。
  读弹窗里第一个 checkbox 的话，"点前 == 点后"在"点『查看』把**别的**那一行
  翻掉了"时照样通过。所以连"整个弹窗的勾选集合"一起读。
- **中文串里别嵌 ASCII 双引号**：`chk("…"因为没采到"…")` 是 Python 语法错误，
  一次报三个。一律用「」。
