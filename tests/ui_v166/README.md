## item 3：删账号要**连盘带表**一起清

用户报的现象是「文件进了共享区」。根因是 `dsapp_user_delete()` 删了 `file_owner`
的行却**没删 `data/files/u<N>/` 那个目录**，而 `dsapp_files_sync_owners()` 每次登录 /
打开管理页都会扫 `^u[0-9]+$` 的目录、把盘上有而表里没有的文件补登记成「无主/公共」
—— 于是死账号的文件又冒出来。

`probe_delacct.py` 量四段：① 无主目录那一栏画得出来、列得出；② 清得掉、清完
**页面上也不再有它**；③ 从「用户与权限」搜出那个号 → 点中那一行 → 确认框明说
管理区一并删 → 确认；④ 回库/回盘对账（账号行、目录、`file_owner` 行三项都空）。

### 这条探针撞出来的三个坑（都写进代码注释了）

* ★★★ **`file_owner` 只删目录不删行** —— 清完无主目录之后，「文件归属」那张卡
  （`SELECT … FROM file_owner`，不碰盘）**照样列着** `left_behind.csv u990001`，
  指向一个已经不存在的文件。② 第一次跑就是这么红的，而红的位置看着像
  "无主目录那一段没重画"。修在 `dsapp_files_orphans_purge()`。
* ★★★ **`vapply()` 的 `USE.NAMES` 陷阱（老 bug，V16.1 起每一版都有）** ——
  见下面单独一节。
* ★★ **探针自己写库，应用不会知道。** `act()` 是 reactive（只依赖 `refresh()` /
  `days()`），而 `C.goto()` 走的是 `window.dsappNav()` —— **前端切页，Shiny 会话
  不换**。所以种完那个号之后服务端手里还是缓存里那份，症状是
  「筛出 0 个（共 22 个）」，看着像"搜索坏了"。③ 现在先 `relogin()` 换个新会话
  再搜，并且**现算**判据（页面说的「共 N 个」必须等于库里现在的账号数，
  不写死 23 —— 写死的话下次跑就红，而红得毫无信息）。

### ★★★ 张表**整个消失**，而探针看不出来（两个判据上的坑）

* **`inner_text` 对 `visibility: hidden` 的元素返回空串。** DT 出错的时候
  htmlwidgets 的处理是 `el.style.visibility = "hidden"` 并把旧的 DOM 原样留着 ——
  于是「表整张没了」和「表里没有这个人」在 `inner_text` 下**长得一模一样**
  （都是空串）。判据改用 `textContent`（不看渲染，看 DOM）**加上**服务端渲染的
  那一句 `筛出 N 个（共 M 个）`。
* **`tbody tr` 数出来是 1，不一定是"筛出一个人"。** 空表时 DT 画的是一行占位
  （`data.frame(提示 = "没有符合条件的账号")`）—— 于是「筛完只剩一行」这条断言在
  **空表**上照样变绿，而它绿的意思是"下面点的可能不是他"这个风险根本没排除。
  ③ 现在把 `筛出 1 个` 单独钉了一条。
* **按 id 点，不要按文字点。** `button:has-text('删除用户')` 在这一页上点不出弹窗
  （报的是「等 `#shiny-modal` 超时」，指向弹窗、不指按钮）。用模块自己的
  `#htadmin-del`。

### ★★★ `vapply()` 的 `USE.NAMES`：搜到"那个从没来过的号"时整张表消失

`vapply()` 默认 `USE.NAMES = TRUE`，而它的规则有一条是「X 是 character 且结果还
没名字 → 把 **X 的值本身**当结果的名字」（给 `sapply` 准备的）。这里的 X 是
`df$last_act`（`MAX(audit_log.at)`），而**一次都没动过的账号是 NA**：

```
names(vapply(NA_character_, f, character(1)))   # NA_character_
data.frame(x = …)                                # row names contain missing values
```

`output$tbl` 整条抛错 → 表消失（`visibility:hidden`），错误只进
`data/logs/app_error.log`。**触发条件是「筛完只剩一行」且那一行 `last_act` 是 NA**
—— 正好是「找出那个从没来过的号、把它删掉」这条最常用的路。长度 ≥ 2 时 R 不走
那一支，所以手工试很容易试不出来。

同一个写法在 `R/mod_admin.R` 的「用户管理」表上也有一份
（`users.last_seen_at` 是**可空列**，实测库里就有 NULL）。两处都加了
`USE.NAMES = FALSE`，`selftest.R` 里配了三条断言：陷阱是真的（不带必须抛）、
两处写法都躲开了、而且这两处**真的在仓里**（不然前一条是在扫空气）。

### ★★★ 顺手挖出来一个**一直在发货的真 bug**：运行时 R 版本比包旧

打包脚本一直写着 `RVER=4.4.2`，而 CRAN 的 `contrib/4.4` 里那些包**是用 4.4.3
编的**。规则来自 R 自己（`base::library` 里的 `testRversion`）：

```r
if (R_version_built_under > current) warning(...)
```

**只有包比 R 新才吭声，包比 R 旧完全静默。** 实测（R 4.4.2，改
`Meta/package.rds` 的 `Built` 一位一位试）：4.3.9 / 4.4.0 / 4.4.1 / 4.4.2 无警告，
4.4.3 / 4.5.0 才警告。⚠️ `Built` 是**从 `Meta/package.rds` 读的**，不是重读
DESCRIPTION —— 第一版测试改错了地方，所以"什么都没发生"。

也就是说：**用户那边每 `library()` 一个包就打一句**
`package 'xxx' was built under R version 4.4.3` —— 64 个包滚一屏英文，看着像
程序坏了。两个平台都中招。改成 `RVER=4.4.3` 之后消失。

⚠️ 顺带把那条自检也修对了：它原来写的是"每个包的 Built 都**等于**运行时"，
**这条永远不可能成立** —— CRAN 是陆续重编的，同一个仓库里 4.4.0/4.4.1/4.4.2/4.4.3
混着（2026-10-05 实测 mac arm64：`4.4.0:4 4.4.1:29 4.4.2:29 4.4.3:31`）。
现在查的是"**没有包比运行时更新**"。

### 字节码能跨到哪一位：**minor，不是 patch**（量出来的）

打包机是 R 4.4.2、包里运行时是 4.4.3 —— 这个组合是**验证过**的正常组合，
不是将就。2026-10-05 用 conda 装的 Linux R 4.4.3 对照系统 R 4.4.2 实测：

### 这一轮改出来的四个坑（都写了注释 + 自检）

1. **★★★ 版本闸门被我自己写空了。** `key()` 原来是
   `paste(v[1:2], collapse=".")` 配 `strsplit(s, "[^0-9]+")` —— 而
   `"R version 4.4.2"` 按非数字切分的**第 1 个元素是空串**，`[1:2]` 拿到的是
   `c("","4")` → `".4"`，**谁来了都是同一个值**。老写法 `[1:3]` 只是碰巧
   因为同样的下标偏移才对。改成先滤空串再取两位。
   ⚠️ 最阴的地方：这个闸门空转时，"补丁版要相等"那条断言**照样绿**，
   只有"跨 minor 要拦住"会红 —— 而它长得完全正常。
2. **打包脚本把 `bin/` 当成了 R 根。** 原写法 `find -printf '%h\n'`（剥一层）
   + 外面 `dirname`（再剥一层）= 剥两层；改成可移植写法时只留了一层 dirname，
   于是搬错了目录，报的是"没有 `runtime/R/bin/Rscript.exe`" —— 看着像下载的
   zip 坏了。**判据换成结构**：哪一层同时有 `bin/Rscript[.exe]` 和 `library/`。
   ⚠️ mac 那份当时**能跑**，但靠的是"tar 里顶层那个 `Rscript` 恰好排在 `bin/`
   前面"这个**归档顺序的运气**，换个顺序就一样坏 —— 一并改成结构判据。
3. **macOS 上跑不了的写法。** `grep -oP` / `find -printf` / `sort -V` / `python3`
   都是 GNU 专有或 Mac 上不保证有的。其中 `! grep -qP ...` 最阴：BSD grep 会以
   退出码 2（用法错误）失败，**取反把"错误"变成了"通过"** —— 在 Mac 上打包时
   这条永远绿。另外 Windows 那份脚本的注释里写着"不用 python3（Mac 上是个壳）"，
   而**同一份脚本下面 50 行就在用 python3**，已改成 R。
4. **`httpuv` 装不上 = Shiny 起不来。** 第一次跑的时候 CRAN 抽风，
   `httpuv` / `xtable` 两个下载失败（`Couldn't connect to server`，
   重跑就好，抓取脚本是可续的）。不是代码问题，但值得记一笔：
   包不全的时候脚本会**当场停**，不会出一个"看着好好的、一用就废"的包。

### ★★★ 加这个链接**真的弄坏过东西**：页脚在 480px 折成两行

而且只在某些宽度下出现。量的结果：加了链接之后 480px 和 600px 都变成两行
（60.6px > 41.6px），**拿掉链接再量一次**确认 480/600 原本是一行 —— 所以这是这一版
自己弄出来的回归，不是老问题。

修法：把「获取最新版 → 最新版」和旁边那句客服一起提前到 **767.98** 那一档换，
并在 ≤575.98 藏掉 `.dsapp-footer-gpu-short`（宽档的那些字在窄屏是纯负担）。
改完 480 / 600 / 700 都回到一行。

⚠️ 但 **360px 上它本来就折行**（内容 423px 塞进 376px 的可用宽度）。这一条**加链接

### ★★★ 两个"改了没反应、也不报错"的坑

**① CSS 加载顺序**：`skins.css` 在 `app.css` **之后**加载，而 `--dsapp-footer-h`
在**两个文件里各定义了一份**（都是 `:root`、权重相同）→ `app.css` 那份一直是**死的**。
于是"在 app.css 里加一条窄屏 `@media` 覆盖"量出来 360px 下 `padding-bottom` 照旧
41.6px，探针红了但**红得完全指不到原因**（`matchMedia` 明明是 True）。现在两份合成
一份（只在 `skins.css`），自检里钉着"只许它定义"。

**② 剥 CSS 注释：`perl = TRUE` 时 `.` 默认不匹配换行**。自检那条"只许 skins.css
定义"第一次是**红的**，红的原因不是代码错 —— 是我在 `app.css` 的注释里**引用了**
那句被删掉的声明（"这里原来也写了一份 `:root { --dsapp-footer-h: 2.6rem; }`"），
而扫描没把注释剥掉。自己写了个 `gsub("/\\*.*?\\*/", ..., perl = TRUE)`，**两次都没剥掉**：

- ① `gsub` 是**逐元素**的，CSS 注释可以跨行 —— 按行传进去一行都剥不掉（要先 `paste`）；
- ② 就算先 paste 成整块还是剥不掉，因为 `.` **默认不匹配 `\n`**，那个模式只能匹配
  **写在同一行里**的注释。

实测两个样本：`"a /*x*/ b"` 剥得掉、`"a /*x\ny*/ b"` 原样留着。危险在于它在"注释恰好
没跨行"时**表现得完全正常** —— 任何人用这种写法剥过 CSS 注释的旧判据都该重新看一眼。

**结论不是"记得加 `(?s)`"，而是别再写第四份剥注释。** 本仓早有 `strip_comments`（R）
和 `strip_js_comments`（JS/CSS，逐字符扫描），而且 `app.css` 的**剥完版本**在
`selftest.R:6011` 就算好了（`css_code`）。现在这一节直接用 `css_code` + `css_rule()`。

### ★ 顺手修掉一处**变松**的判据

抠那条 `@media` 块，第一版写的是"从 `@media` 到下一个 `@media`"。变异测试打出窗口
内容才看见它**越过了媒体查询自己的 `}`**，把后面一串顶层规则也圈了进来。后果不是
报错，是这条断言**变松**：把那对长短规则整个搬到媒体查询**外面**（宽屏也被换成短
文案，真的坏），窗口里照样找得到它，断言照样绿。改成 `dsapp_block_at()` 按花括号配对。

### ★★ 改完之后，**全量自检里红了一条老断言** —— 而且红得对

`selftest.R` 里有一条 V6 时代就有的："页脚留了等高变量，主区域按它补了
padding-bottom"。它查的是 **`app.css` 里有没有这个变量**；而这次恰好把 app.css 那份

这不是"老断言过时了删掉就行"：它管的两件事（变量在 + `#app_root` 按它补
padding-bottom）一件都不能松。改法是**把它的目光挪到变量真正在的地方**
（`skins.css` 的 `:root`），并补了 `skins_code` / `skins_rule()` 两个前置定义；
两半都拿变异验过：删掉 skins.css 里那个变量 → 红；把 `#app_root` 的
`padding-bottom` 换成死数字 `41.6px` → 红。

⚠️ 顺带清掉三处**注释里的旧地址**（`www/codex.css` 顶部写着"定义在 app.css 的
`:root` 里"、`www/app.css` 那条"固定高度 2.6rem"、`R/utils.R` 同款）。注释写错
不会有任何东西变红，只会让下一个人照着它推错。
