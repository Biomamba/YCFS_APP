## 这道题为什么非得上浏览器

R 那一侧的 32 条断言已经把"函数对不对、盘上有没有"验穿了。下面这几条它一条
都验不到：

* 按钮**真的**变 disabled、真的出现「正在补齐…」、跑完真的**变回**可点。
  `disabled` 是在 `renderUI` 里算出来的，静态扫源码看不出它有没有生效 ——
  而失效的形态恰恰是"点了没反应"（用户报的就是这个）。
* 补齐完成那句提示**真的弹出来**，而且报的数是对的。这是 V16.9「不再静默」
  唯一能被用户看见的地方。
* ★★ **界面真的画出来了**：进同步文件夹、按名称倒排，第一行必须从
  `seed_0299.txt` 变成 `seed_0359.txt`。库里对了不代表画出来了（本仓有账：
  `renderUI` 没读失效源 → 写库成功但页面一动不动）。

## ★★ 缺口必须**真调 `dsapp_sync_artifacts()`** 种出来

`seed_overlimit.R` 的存在就是为了这个。**不能在探针里自己往 `data/files/`
拷文件** —— 自己拷出来的"缺"缺的恰好是 `sync_dirs` 那一行，而**那一行是这道题
的全部关键**：老的 `dsapp_sync_backfill()` 拿 `sync_dirs` 当判据（有行就跳过），
而撞过上限的对话**必然**有那一行，于是它精准地跳过每一个需要补的对话。

自己拷文件种出来的场景，在**旧代码上也是绿的** —— 整条探针会变成"验了个空气"。
（本仓老账：变异测试的变异可能是空转的。）

## 探针里那个"同一个量前后各量一次"的写法

```
补齐前：倒排第一行 == seed_0299.txt   ← 缺口在界面上看得见 + 倒排真的生效
补齐后：倒排第一行 == seed_0359.txt   ← 界面真的重画了
```

一个量、两帧。只测"结果是 359"的话，那个断言在**什么都没补的旧代码**上也会
因为别的原因（比如倒排根本没生效、读到的是 `seed_0000.txt`）而红得莫名其妙；
而只测"前"那一帧，就永远绿。

顺手：`dom = "tp"`（`R/mod_files.R` 里那张表）意味着**没有 info 元素**，
读不到"共 N 条"，每页又只有 12 行 —— 所以要问"最新那批在不在"，就得让最新
那批出现在第一页上（点两下名称列表头 = 升 → 降）。

## 三个"看起来像通过"的坑（都写进代码注释了）

* **通知可能已经过期**（默认 8 秒），而等后台跑完最多要 180 秒。所以那条断言
  是"在就验、不在就打印一句"，硬判据放在界面 + 库 + 盘那三条上 ——
  把一条**可能因为慢而红**的断言当成主判据，会训练出"这条红了不要紧"的习惯。
* **探针自己写库，应用不会知道**：`seed_overlimit.R` 是**另一个进程**写的，
  当前 Shiny 会话对那几行一无所知 → 必须 `relogin()`（重新登录 = 换一个会话）。
  用 `C.wait_awake()` 等不了：reload 时 cookie 还在，登录页一帧都不出现。
* **`--no-environ`**：仓库根那份 `.Renviron` 指着生产库，而 Rscript 会读
  **cwd** 的 `.Renviron` 并**盖掉**继承的环境变量（本仓为此在生产库里种过
  东西）。子进程一律带 `--no-environ`，data_root 只由命令行给。
