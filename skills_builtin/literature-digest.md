# 文献速递

## 什么时候用这条技能

用户给出一组关键词（或者一句"帮我看看最近 XX 方向有什么新文章"），要你去找文献、
筛出相关的几篇、并按深浅两档整理出来。也适用于：查某个方法学细节出自哪篇、
某个结论现在有没有更新的证据、某个方向这两年有没有人做过。

反过来，如果用户是要**写**一篇综述或论文，那是 `academic-research` 那条技能的活；
如果用户手里已经有一篇具体文献要精读，直接从那篇开始读就行，不必先检索。

---

## 一、先想清楚"检索什么"，再动手

最容易白费力气的做法是拿用户的原话直接去搜。搜之前先把它翻译成**检索式**：

- **抽概念**。一句话里通常有 2–4 个真正的概念（疾病 / 组织 / 方法 / 数据类型），
  把它们拆出来。形容词、程度词、"最新的"这类都不是概念。
- **补同义词**。每个概念列 2–4 种写法：全称与缩写（`spatial transcriptomics` /
  `ST`）、英美拼写（`tumor` / `tumour`）、新旧命名（`NGS` / `high-throughput
  sequencing`）。同义词之间用 `OR`，概念之间用 `AND`。
- **中文关键词必须先转成英文**。Europe PMC / PubMed / bioRxiv 基本只收英文文献，
  直接拿中文去搜会返回零条 —— 而"零条"很容易被误读成"这个方向没人做过"。
  这一步没有捷径，靠你对这个领域的了解；拿不准就把几种可能的英文写法都搜一遍。

举一个：关键词"肝癌 单细胞 免疫治疗" →

```
(hepatocellular carcinoma OR HCC OR liver cancer)
  AND (single-cell OR scRNA-seq OR single cell RNA sequencing)
  AND (immunotherapy OR immune checkpoint OR PD-1)
```

## 二、查哪些库

按下面的顺序试。**前两个是主力**，后两个是补充：

| 库 | 入口 | 什么时候用它 |
|---|---|---|
| Europe PMC | `https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=...&format=json` | 默认首选。覆盖面广、返回 JSON、带 PMID 和 DOI，开放获取的还给全文链接 |
| PubMed E-utilities | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=...&retmode=json` | Europe PMC 结果不全时交叉验证；`efetch.fcgi` 取结构化摘要 |
| bioRxiv / medRxiv | `https://api.biorxiv.org/details/biorxiv/2024-01-01/2024-12-31` | 找**还没正式发表**的最新工作。做前沿方向时这个往往比正式库更有用 |
| Crossref | `https://api.crossref.org/works?query=...` | 补 DOI、期刊、作者单位信息最准 |

用 `curl` 直接查就行，都是公开接口、不需要 Key。几个实操要点：

- **分页**。Europe PMC 用 `pageSize`（最多 1000）+ `cursorMark` 翻页；
  PubMed 用 `retstart` / `retmax`。别只看第一页就下结论。
- **先看命中总数再决定要不要收窄**。几十条是合适的工作量；几千条说明检索式太宽，
  得加概念或加年份；**零条先怀疑是检索式写错了**（多半是同义词没覆盖到）。
- **`retmode=json`**。不加的话拿回来的是 XML，还得再解析一道。
- 被限流（HTTP 429）就退避几秒重试，别在循环里硬打。

## 三、怎么筛

检索结果按"和用户问题的相关度"排，**不是按期刊影响因子排**。逐条看标题和摘要，
用一个明确的判断：*这篇如果读完了，能回答用户问的那个问题吗？* 不能就丢掉。

丢掉的时候留意两类：**方法学文章**（没有新结论，但可能是用户要的方法出处）
和**综述**（本身不是新结果，但能快速给出这个方向的全局）。这两类别当噪音删掉，
单独标出来。

## 四、两档怎么分

- **精读**：真的读了。至少是完整摘要 +（能拿到的话）全文的方法与结果段。
  产出要写清楚：研究问题 / 数据与方法 / 主要结论 / 和关键词的关系 / 局限。
- **略读**：扫了摘要，判断值得知道。产出三四句话：做了什么、结论是什么、
  为什么值得一看。

⚠️ **略读不是"写得短一点的精读"**。分两档的意义在于让用户知道**哪些结论可以放心引用、
哪些只是有个印象**。把略读写成了缩短版精读，这个区分就没了。
哪几篇没拿到全文，要在名字后面明确标出来。

## 五、三条硬约束

1. **一条都不许编。** 这是文献检索里最容易犯、后果最重的错。你对某个方向"有哪些
   经典工作"有很强的先验记忆，那些记忆里的条目看着非常真实，但 PMID / DOI 经常
   对不上号。**只收录这次真的检索回来的条目**，每一条都要带上能点回去的标识
   （优先 DOI，其次 PMID）。编不出标识的条目一律不收 —— 宁可少给几篇并说明
   "只找到这么多"，也不要凑数凑到用户要的篇数。

2. **摘要不等于全文。** 只有摘要时，样本量、对照设置、统计方法、置信区间这些
   **看不到就是看不到**，写"摘要未提供"。绝对不要照着摘要把方法段补出来 ——
   补出来的方法学又具体又像真的，是这几类错误里最难被发现的一种。

3. **接口出问题要照实说。** 某个库打不开、被限流、返回空，都要写进产出，
   并说明换用了哪个入口（写在文末的「附：检索记录」里，不要写成正文）。
   静默降级会让用户以为"这个方向只有这几篇"。

## 六、产出什么

主产出是工作目录里的 `文献速递.md`。

⚠️ **它是一份「文献阅读汇报」，不是检索过程的画外音。** 读它的人要知道的是
**这些文献说了什么**，不是你怎么把它们找出来的。正文一律从文献内容写起；
检索式、命中数、筛选经过这类过程信息**全部压到最后一节「附：检索记录」**，
写成一张短表。正文里不要出现"我先检索了…接着筛选了…"这种叙述。

```
# 文献速递：<关键词>

## 这批文献讲了什么
（开篇直接是内容：这个方向的主要结论、哪几篇给出了关键证据、有没有分歧）

## 精读（N 篇）
### 1. <标题>
- **出处**：期刊, 年份 · DOI: 10.xxxx/xxxxx
- **作者**：First Author et al.
- **研究问题**：
- **数据与方法**：
- **主要结论**：
- **和关键词的关系**：
- **局限**：

## 略读（M 篇）
### 1. <标题>（期刊, 年份 · DOI: ...）
做了…。结论是…。值得看是因为…。

## 一句话总览
这个方向现在走到哪了、还缺什么。

## 附：检索记录
（一张短表：库 / 检索式 / 命中数 / 备注。放在全文最后，几行就够 ——
 它是备注，不是开场白。）
```

`文献速递.md` 写完，在对话里**只说路径和一句概况**（找到了几篇、最重要的那篇讲了
什么），不要把全文贴回对话 —— 那会占掉上下文，而且用户要的是文件。

## 来源与许可

本技能为平台自撰，MIT 许可。

它使用的检索入口全部是各机构的**公开 API**，无 Key、无需注册：

- Europe PMC RESTful API — <https://europepmc.org/RestfulWebService>（EMBL-EBI，
  数据来自 PubMed / PMC / Agricola / 预印本库）
- NCBI E-utilities — <https://www.ncbi.nlm.nih.gov/books/NBK25501/>（美国国家生物
  技术信息中心；有使用频率限制，批量请求需自行退避）
- bioRxiv / medRxiv API — <https://api.biorxiv.org/>（Cold Spring Harbor Laboratory）
- Crossref REST API — <https://api.crossref.org/>（Crossref，DOI 注册机构）

⚠️ 各接口的使用条款、频率限制和字段定义以**各库官方文档**为准 —— 上面写的字段名
可能随接口版本变化。检索到的文献元数据（标题、摘要、作者）版权归原作者与出版方，
本技能的产出仅用于个人阅读与整理，**二次分发或用于出版前请自行核对授权**。
