# 学术论文写作与同行评审

## 什么时候用这条技能

用户要写论文、学位论文、会议论文、政策简报或文献综述，要你帮忙搭结构、写某一章、
写摘要、检查引用；或者用户手里已经有一份稿子（自己的或别人的），要"以审稿人角度看看"；
又或者用户收到了审稿意见，要解析意见、规划怎么改、写 point-by-point 答复信。

反过来，如果用户只是想做文献调研、查证某个事实、写一份普通分析报告（不是投稿稿件），
不要套这条技能的结构——那是另一回事。

**贯穿全流程的一条底线**：任何断言都必须有出处或由本文自己的数据支撑。核实不了的数字
和文献宁可留空、标出来让用户补，也不要写一个"看起来合理"的。这条比下面所有具体规则都优先。

---

## 一、先定骨架：论文类型决定结构

结构选错是最贵的错误——它会在写完一半时才暴露，且几乎必然导致重写。**先确认研究问题
的性质，再选结构**，不要反过来。

| 论文类型 | 适用条件 | 典型字数 |
|---|---|---|
| IMRaD（引言-方法-结果-讨论） | 有原始数据收集与分析 | 5000–8000 |
| 主题式文献综述 | 综合已有研究、指出空白、提研究议程 | 6000–10000 |
| 理论分析 | 发展、批判或扩展一个理论框架 | 5000–8000 |
| 案例研究 | 深入分析特定机构/项目/事件 | 4000–7000 |
| 政策简报 | 给决策者的循证建议 | 2000–4000 |
| 会议论文 | 会议投稿，进展中或已完成的研究 | 2000–5000 |

常见错配：因果问题却选了文献综述结构；没有数据却选了 IMRaD；题目适合案例研究却选了
政策简报；3000 字却要写 IMRaD（装不下）。发现错配就停下来向用户说明，并给出 1–2 个
替代结构及理由，而不是硬着头皮往下写。

**字数分配**（以 IMRaD 6000 字为例，其它结构同理按比例）：引言 15%、文献综述 25%、
方法 15%、结果 20%、讨论 20%、结论 5%。写完每一章就核对一次进度，不要等全文写完
才发现超了 30%。

## 二、逐章写什么

### 引言：按 CARS 三步走，不要按时间顺序铺陈

引言是说服问题，不是总结问题。读者读完必须被说服三件事：这个领域重要、有个具体的
空缺、本文补上了它。按顺序起草：

1. **建立领域**（1–2 段）——为什么这个领域现在关心它（政策压力、实证异常、方法转向）；
   该领域已知什么；本文建立在哪些具体发现上。**综合，不要罗列**（"A 发现 X。B 发现 Y。"
   是文献堆砌）。这里的每一条领域断言都必须能追到已检索到的文献，无出处的"重要性"
   断言在自审阶段会被打回。
2. **建立空缺**（最短、最锐利）——人群/情境/机制/方法上的空白、相互冲突的发现、
   已知事实解释不了的现象。**空缺必须由前面的文献综述授权**：如果证据不支持
   "X 在 Y 中尚未被研究"，就退一步说证据实际支持的话（"Y 中的证据仍限于 Z 设计"）。
3. **占据空缺**（具体、不闪烁）——一句话陈述研究目的，主动语态、具体（"本研究估计…"
   而不是"本研究旨在探讨…"）；研究问题/假设与前面定义的空缺逐字对应；预告贡献。

**两个高频致命伤**：

- **全称否定**。"没有任何研究做过 X"是不可验证的断言，也是编辑直接退稿的常见导火索。
  改成有检索边界的说法："我们检索了[具体数据库]，覆盖[时间与设计范围]，未发现…"。
  有边界但没记录检索执行日期的，同样算不可验证。
- **空缺与目的错配**。空缺讲的是"机制"，目的写的是"流行率"——审稿人一眼就看出来。
  目的句是全文被引用最多的一句，先起草它，再写引言其余部分。

引言占正文 10–15%。一段一个 move 是安全默认，move 1 可以占两段。

### 标题

好的实证标题 = 核心概念（前置）+ 具体限定（人群/情境/机制）+ 可选的设计信号
（"a longitudinal study"、"evidence from X"）。15 词以内，除非目标期刊惯例更长。

写 3–5 个候选，逐条对照检查：最重要的概念是否在前 3–4 个词里；是否包含本领域的人
真会用来搜索的词（与摘要关键词对齐）；没有"A study of"、"An investigation of"、
"Toward an understanding of"这类空转开头；**声称的强度与设计匹配**——横断面数据
不要用因果动词；是否具体到能排除掉五十篇它并不想指的论文。

### 摘要

**结构（5 组件）**：背景 1–2 句 → 目的 1 句 → 方法 1–2 句 → 发现 2–3 句（给具体数字，
百分比、效应量）→ 意义 1–2 句。医学与社科多用带标签的结构式摘要（Background / Objective /
Method / Results / Conclusion），人文学科多用不分段的一段式。

**长度与关键词**：

| 论文类型 | 中文摘要 | 英文摘要 | 每语关键词数 |
|---|---|---|---|
| 标准 | 300–500 字 | 150–250 words | 5–7 |
| 会议 | 300–800 字 | 200–500 words | 5–7 |
| 扩展摘要 | — | 500–1000 words | — |
| 学位论文 | 500–1000 字 | 至多 350 words | 5–7 |

政策简报没有摘要，它的交付物是执行摘要（200–300 字 + 3–5 条要点）。目标是期刊的，
期刊规定的字数优先于上表。

**中英双语摘要的硬要求**：两份摘要**各自独立撰写**，不是互译。两者覆盖相同的要点、
顺序一致、关键数字一致。不要写成"先把中文翻成英文"。

**关键词**：核心概念 2–3 个 + 情境 1–2 个 + 方法 0–1 个 + 学科 1 个。小写（专有名词除外），
与标题互补而不是重复标题里的词。摘要里不要有引用，不要有未定义的缩写。

### 方法、结果、讨论

每节先问"读者在这里的'那又怎样'是什么"，再决定怎么写：

| 章节 | 读者的疑问 | 你的任务 |
|---|---|---|
| 引言 | 我为什么要关心？ | 用真实后果或知识空白抓住他 |
| 文献综述 | 已知的东西缺了什么？ | 向空缺推进，不要只做总结 |
| 方法 | 我能信这些结果吗？ | 展示严谨性，主动交代局限 |
| 结果 | 你到底发现了什么？ | 先给发现，再给统计检验 |
| 讨论 | 这对领域意味着什么？ | 回到空缺，明确说出增量 |
| 结论 | 我该记住什么？ | 一句话说清贡献 |

**时态**：文献综述报告他人发现用过去时（"Smith (2024) found…"），陈述持续成立的理论
用现在时；方法、结果用过去时；讨论解读用现在时；结论的启示用现在时/将来时。

**hedging 要分级**：弱（may / might / could）、中（suggests / indicates / appears）、
强（demonstrates / establishes / confirms）。需要 hedge 的场合：待重复的结果、
从相关数据得出的因果主张、小样本的推广、有替代解释的解读。**不需要 hedge 的场合**：
报告事实数据（"回答率 78%"）、描述方法（"我们用了主题分析"）、已确立的事实。
最大的 hedge 错误是连自己的研究结果都过度对冲。

### 语言：改掉这几类写法

**冗余短语**：in order to → to；due to the fact that → because；a large number of →
many；at the present time → currently；has the ability to → can；conduct an
investigation of → investigate；in spite of the fact that → despite。

**含糊表达必须换成具体**："many studies" → "several studies (e.g., Chen, 2023; Smith, 2024)"；
"a significant impact" → "a 23% increase in retention rates"；"in recent years" →
"since 2020"；"some researchers" → 点名并给引用；"it is well known that" → 给来源或删掉。

**清嗓子开头**：删掉"In the realm of…"、"It's important to note that…"、"It is worth
mentioning that…"、"When it comes to…"、"With that being said…"。以及描述"本文将要做什么"
而不是去做它的元评论："This section will discuss…" → 直接讨论。**例外**：引言末尾的
路线图句（"第 2 节回顾文献；第 3 节描述方法"）是标准做法，保留。

**术语一致性**：同一概念不要为了避重复而换词（students → learners → participants →
subjects 在同一段里轮换，只会让读者困惑）。学术写作里术语一致是优点。但要保留真正
有区别的技术术语。

**不要凑三分法**。不是每个论点都能拆成三点；两个强论点胜过三个注水的。段落长度由论点
需要决定，不要为了"看起来有变化"而人为拆合。

## 三、写完初稿后的自检清单

按顺序过，每一条都针对具体问题，不是打分表。

1. **清晰度测试**——逐段问："删掉这段，论文还成立吗？"成立且没损失 → 删；成立但丢了
   上下文 → 保留但压缩；不成立 → 这是承重段，值得反复打磨。多数机器生成的学术文本
   失败在每段都被同等对待，承重段和过渡段一个待遇。
2. **读者旅程**——每个位置读者能否回答：我在哪（结构）？我为什么在这（与研究问题的
   关联）？我该带走什么（本节的要点）？下一步去哪（过渡）？四问有一个答不上就改。
3. **禁用词复核**——delve、tapestry、landscape、pivotal、crucial、foster、showcase、
   testament、navigate、leverage、realm、embark、underscore、multifaceted、nuanced、
   comprehensive、robust、intricate、cornerstone、paradigm、synergy、holistic、
   streamline、cutting-edge、groundbreaking。**不是禁用，是提示："这个词是这里最精确
   的词吗？"** 是本领域标准术语的除外（统计学的 "robust estimator"、哲学的
   "paradigm shift"、生态学字面意义的 "landscape" 都保留）。
4. **标点复查**——破折号是否在打断论证？能改成逗号、括号或独立句的就去改。
5. **零引用孤儿**——正文引用与参考文献列表必须完全一一对应，多一个少一个都是错。

## 四、审稿人视角：五席位评审

这是这套方法最有价值的部分。**自审时把自己劈成五个角色分别写报告，谁也不许看别人的
结论**（先各自写，最后再合并）——否则会出现"读完全文再合理化评分标准"的漂移，以及
为避开重复而隐瞒发现。五个席位：

| 席位 | 只管什么 |
|---|---|
| 期刊匹配审稿人 | 期刊契合度、原创性、对读者群的意义。**不深挖方法** |
| 审稿人 1（方法） | 设计严谨性、抽样、数据收集、分析方法选择、统计效度、效应量、可复现性、数据透明度 |
| 审稿人 2（领域） | 文献覆盖完整性、理论框架适当性、论证准确性、对领域的增量贡献、漏引的关键文献 |
| 审稿人 3（跨学科） | 跨学科连接与借鉴机会、实际应用与政策含义、更广的社会/伦理含义、挑战根本假设 |
| **魔鬼代言人**（固定席位） | 核心论点的最强反驳、cherry-picking、确认偏误、逻辑链、过度推广、被忽略的替代解释、利益相关方盲点、"那又怎样"测试 |

### 每个席位的报告结构

**总体评估**（150–250 词）：前两句说这篇做了什么（主题、方法、主要发现）；接着两句
从本席位视角给整体质量判断；再讲你实际发现的、最关键的一两个优点和缺点；最后给推荐
理由。

**优点**：列出**你真正找到的每一条**，不设上下限，**不要为凑数编造**。空列表是合法的。
每条要有具体标题、**类型化证据锚点**、说明为什么算优点。不要给优点标严重度。

**缺点**：同样不设上下限。每条必须包含：具体标题、问题描述、**为什么是问题**、
**具体改进建议**、证据锚点、严重度、逐条置信度。

**证据锚点**（每条发现只带一个，与证据类型匹配）：

| 类型 | 用于 | 定位内容 |
|---|---|---|
| `text` | 稿件明确陈述的主张 | **逐字引用（≤ 25 词）** + 页码/节/段 |
| `table` | 数值/表格证据 | 表号 + 行/列，或所引的具体单元格值 |
| `figure` | 视觉证据 | 图号 + 面板/特征 |
| `equation` | 形式化/数学内容 | 公式号 + 有问题的项 |
| `dataset` | 稿件中报告的数据/工件属性 | 工件名 + 有问题的属性 |
| `absence` | 遗漏——缺声明、缺章节、缺分析、缺文献 | `absence: <该出现的位置> — expected <预期内容>; checked <你查过哪些位置>` |

**Critical 与 Major 级发现必须带合格类型的锚点**。锚不出任何适用类型的 Critical/Major
主张还不算发现——要么去做能产生锚点的检查，要么降级为"给作者的问题"。`absence` 锚点
只有写清"你在哪里找过"才可检验。"论文从未说明 X"必须补上"已查：方法、局限、附录"。

**严重度只有一个判据——决策影响**（逐条独立判断，不从邻近发现继承）：

| 级别 | 判据 | 修改要求 |
|---|---|---|
| Critical | 这一条不改，核心主张就不成立或无法接受 | 接受前必须解决 |
| Major | 显著削弱对核心主张的信心，需要实质重分析/重写/补数据，但核心仍站得住 | 实质修改 |
| Minor | 改了更好，不影响核心主张 | 有限修改 |

语气是**语域**，不是严重度：礼貌措辞不降低级别，尖锐措辞不提升级别。

**给作者的问题**：2–4 个真正需要回答、答案可能改变论文质量或方向的问题。不要修辞性
提问。

**次要问题**：语言/语法、引用格式、图表、版面。这些是低于发现门槛的编辑级条目。

### 七维度判据

对每个适用维度给一个**类别判定**（不折算成分数、权重、总分、百分比或排名）：

| 维度 | 核心问题 |
|---|---|
| 原创性 | 相对相关文献与目标期刊，做了什么可辩护的贡献？ |
| 方法严谨性 | 设计、执行、分析、报告能否支撑所做的推断？ |
| 证据充分性 | 每个实质主张是否有类型/质量/相关性/覆盖度都合适的证据？ |
| 论证连贯性 | 问题、空缺、研究问题、方法、发现、启示是否构成可追溯的论证？ |
| 写作质量 | 是否精确到可被审阅和使用？**不要把语言润色等同于研究质量** |
| 文献整合 | 是否为问题、概念脉络、替代方案、贡献批判性地整合了必要文献？ |
| 意义与影响 | 声称的理论/实证/实践/政策含义是否从证据中得出、对目标读者重要？ |

判定五级：`EXCEEDS` / `MEETS` / `PARTLY_MEETS` / `DOES_NOT_MEET` / `NOT_ASSESSED`。
**不要机械地把标签计数映射成接受/小修/大修/拒稿**。每条判定要带：判据来源（期刊标准、
报告规范、文章类型预期）、证据锚点、理由、不确定性与范围限制、**是否影响推荐决定**。

**证据充分性上没有普适的最少文献数或"同行评议来源占比"**。文献需求随领域、文章类型、
主张广度、证据基础和期刊而变。只有在目标期刊、报告规范或协议明确规定了数字要求时，
才能引用那个具体数字——并且要引它的出处，不要外推。

### 编辑决定

四档决定的判据：

- **接受**：所有适用核心判据被正向验证；没有未解决的决策性弱点；至少 3/4 审稿人推荐
  接受或小修；没有未解决的重大问题。
- **小修**：论文基本可接受，剩余问题有限；没有需要重构核心论证或方法的问题；
  至少 3/4 推荐接受或小修；问题可在 2–4 周内解决。修订后通常不再送外审。
- **大修**：一个或多个实质弱点需要大幅修改，但**可修复而非致命**；至少 2/4 推荐大修
  或更好；需要 6–8 周。修订后重送外审。一般最多允许 2 轮大修。
- **拒稿**：某核心判据存在根本性、不可修复的失败；或论文无法通过修改变得适合本刊；
  或至少 3/4 推荐拒稿。拒稿亚型：超出范围 / 根本缺陷 / 贡献不足 / 不成熟 /
  鼓励重投（有潜力但需根本重构）。

**决定矩阵**（期刊匹配审稿人 + R1/R2/R3 → 建议）：

| 四位审稿人的推荐 | → 决定 |
|---|---|
| 接受 ×4 | 接受 |
| 接受 接受 接受 小修 | 接受（附建议） |
| 接受 接受 小修 小修 | 小修 |
| 小修 ×4 | 小修 |
| 小修 小修 小修 大修 | 小修到大修之间（看具体问题） |
| 小修 小修 大修 大修 | 大修 |
| 小修 大修 大修 大修 | 大修 |
| 大修 ×4 | 大修 |
| 大修 大修 大修 拒稿 | 大修（最后一次机会） |
| 大修 大修 拒稿 拒稿 | 拒稿（鼓励重投） |
| 大修 拒稿 拒稿 拒稿 | 拒稿 |
| 拒稿 ×4 | 拒稿 |

**分歧处理**：均分（如 接受+接受+拒稿+拒稿）时深入分析分歧原因，按"证据优先、专业
优先"仲裁；真正无法消解的，**记录分歧**并让作者在修订中回应，不要默认向更严的一侧
取整。单个离群意见（小修+小修+小修+拒稿）：仔细看拒稿理由，理由成立且其他人漏了 →
升级为大修；理由不充分 → 维持小修但在决定信中提及。

**升级/降级规则**：小修但修订不完整 → 可升级为大修；大修但修订优秀 → 可降级为小修
或接受；大修但修订不足 → 可拒稿（不鼓励无限修订循环）；超过 2 轮大修 → 强烈建议
直接接受或拒稿，不再延长。

**两条对称性原则**：接受结论和拒稿结论承担**同样的举证责任**——接受要正向、有锚点地
验证每条判据成立，拒稿要有锚点地证明判据失败，两个方向都没有更宽的"谨慎余量"。
决定只跟随判据，**不跟随接受率的经验分布**——某一轮拒得多不代表这一轮审得好。

### 魔鬼代言人报告（单独格式）

不给推荐，只给发现：**最强反论**（200–300 词）→ 问题清单（CRITICAL / MAJOR / MINOR，
带维度和位置）→ 被忽略的替代解释/路径 → 缺失的利益相关方视角 → 观察（非缺陷）。
八项检查：核心论点挑战、cherry-picking、确认偏误、逻辑链验证、过度推广、
替代路径分析、利益相关方盲点、"那又怎样"测试。

**魔鬼代言人的 CRITICAL 必须被显式裁决**：验证成立的或真正悬而未决的，阻止直接接受；
被裁决为不成立的，记录理由后不单独否决。**不能静默绕过**。但要注意对称性：一条未经
验证的负面断言，其决定权不高于一条未经验证的正面断言。

### 审稿人常见陷阱

| 陷阱 | 表现 | 纠正 |
|---|---|---|
| 过度苛责 | 不提真实优点，把校对级问题和决策性问题混在一起 | 承认真实优点，区分决策性发现与文字编辑 |
| 确认偏误 | 只找支持自己预设的证据 | 主动寻找反证与替代解释 |
| 偏好投射 | 用自己偏爱的方法当标准 | 问"作者的方法能否回答他的问题" |
| 范式偏见 | 用错误的范式标准评判 | 按论文所属研究范式和文章类型选用判据 |
| 声望偏见 | 看机构/作者而非稿件证据 | 只看证据 |
| 新颖性偏见 | 惩罚重复研究或增量工作 | 复现与边界检验同样有价值 |
| 篇幅偏见 | 看页数、参考文献条数 | 看证据与论证覆盖 |
| 语言歧视 | 把非母语表达当成质量问题 | 区分"意义不清"与"表面不地道" |
| 方法论隧道视野 | 只批方法，不问问题本身是否重要 | **先看贡献，再看方法** |
| 见木不见林 | 列 20 个小问题，漏掉那个致命缺陷 | 永远把最重要的单一问题放在最前面 |

**起草完审稿意见后问自己**：(1) 这篇论文按现状发表会不会误导读者？（会 → 大修或拒稿）
(2) 作者能否在一个修改周期内合理解决我的关切？（不能 → 拒稿）(3) 我对这篇是否比对我
自己的作品更苛刻？(4) 我是否承认了发现的每条真实优点、且没编造任何一条？
(5) 即使论文被拒，我的审稿是否仍能帮到作者？

### 审稿伦理

保密；有合作/竞争关系就回避；**不得使用审稿中看到的未发表想法**；不因作者性别、种族、
机构、国籍而偏见；避免人身攻击与贬损语言；怀疑数据造假时报告给期刊主编，由期刊启动
调查程序。**审稿人不得修改稿件**——所有评审输出都是独立文档，只审不写。

## 五、方法学与统计：审稿人盯什么

### 必报项（缺一项就是一条发现）

- 描述统计：均值必须配对标准差（**不要用标准误冒充**）；总样本量与各组样本量都要报；
  范围或四分位距；分类变量同时报频次与百分比。
- **效应量与检验配对**，参照下表；并且要解读量级，不能只丢一个数字。
- 关键估计要报 **95% 置信区间**，格式 `95% CI [下界, 上界]`（方括号）。
- 精确 *p* 值（如 *p* = .032）；*p* 很小时写 *p* < .001，**写 *p* = .000 是错的**（软件原始输出）。
- 先验声明 α 水平；多重比较要说明用了哪种校正（Bonferroni / Holm / FDR）。
- **不显著的结果也要完整报告**，不许只挑显著的写。
- 先验功效分析：目标功效（通常 ≥ .80）、假设效应量及其来源、α、所需样本量、所用工具。
- 缺失数据：每个变量的缺失量与比例、缺失机制（MCAR / MAR / MNAR）的讨论、处理方法
  （列删 / 配对删 / 多重插补 / FIML）、不同处理下的敏感性分析。

### 效应量与惯例基准

| 分析 | 效应量 | 小 / 中 / 大 |
|---|---|---|
| *t* 检验 | Cohen's *d* | 0.2 / 0.5 / 0.8 |
| ANOVA | *η*²、partial *η*² | .01 / .06 / .14 |
| 相关 | *r* | .10 / .30 / .50 |
| 回归 | *R*²、*f*² | *f*²：.02 / .15 / .35 |
| 卡方 | Cramér's *V*、*φ* | *V*：.10 / .30 / .50（*df*=1） |
| 优势比 | OR | 1.5 / 2.5 / 4.3 |

### 常用分析的检查点

- **回归**：报 *R*²、调整后 *R*²、模型 *F*；系数表含 *B*、*SE*、*β*、*t*、*p*、*B* 的
  95% CI；多重共线性看 **VIF（> 10 是红线，部分领域要求 < 5）**；残差诊断（正态性、
  同方差、线性、Cook's *D* 离群点）。逻辑回归按 **EPV 规则：每个预测变量至少 10–20 个事件**。
- **ANOVA**：报 *F*(*df*1, *df*2)；主效应显著要做事后比较（Tukey / Bonferroni /
  Games-Howell）；析因设计要解读交互；重复测量要报 Mauchly 球形检验与
  Greenhouse-Geisser / Huynh-Feldt 校正。
- **SEM**：样本量通常 ≥ 200，或为估计参数个数的 5–10 倍；**至少同时报 4 个拟合指标**——
  CFI/TLI ≥ .95（≥ .90 可接受）、RMSEA ≤ .06（≤ .08 可接受，须报 90% CI）、
  SRMR ≤ .08、χ²/*df* ≤ 3；标准化载荷 ≥ .50（理想 ≥ .70）；SEM 前先做 CFA；
  CR ≥ .70、AVE ≥ .50。
- **多层模型**：说明每一层；报 ICC（> .05 支持用 MLM）；层-2 单元建议 ≥ 30；
  说明中心化方式；用 deviance / AIC / BIC 比较嵌套模型。
- **卡方**：所有单元格期望频次 ≥ 5，否则用 Fisher 精确检验；显著时看标准化残差。
- **非参数**：说明为什么不用参数检验；方法配对要正确；Mann-Whitney 报
  *r* = *Z*/√*N*。

### 统计红旗（先按优先级排查，再定严重度）

排查优先级（高/中/低）**不是严重度**——一条红旗落实成缺陷时，严重度仍按 Critical /
Major / Minor 依决策影响重新判定。

- **P-hacking 迹象**：大量 *p* 集中在 .04–.05（高）；只报显著结果（高）；无预设停止
  规则（高）；分析策略非先验（中）；事后拆子组找显著（中）；大量剔除离群值且标准不清（中）。
- **HARKing**：假设与结果完美吻合、无一例外（中）；文献综述明显是事后建构（高）；
  假设方向反转却称"如预期"（高）。
- **样本量**：回归中 *N* < 10 × 预测变量数（高）；无功效分析（中）；样本流失未解释（中）；
  SEM *N* < 200 且无小样本校正（中）；层-2 单元 < 30（中）。
- **多重比较**：3 组及以上用多次 *t* 检验代替 ANOVA（高）；多因变量未校正（中）；
  试了多个模型只报"最好的那个"（高）。
- **假定违反**：报告了违反却仍用原分析（高）；VIF > 10 且未处理（高）；假定检验完全
  缺失（中）；拿中心极限定理当借口而不做检验（低）。
- **数字自洽**：**由自由度反推的 *N* 与所报 *N* 不符（高）**；正文与表格数字矛盾（高）；
  效应量与原始数据算不出（高）；**GRIM/GRIMMER——离散尺度数据的均值或标准差在给定
  *N* 与精度下不可达（高）**；*p* 与检验统计量和 *df* 对不上（高）；*p* = .000（低）；
  未说明统计软件及版本（低）。
- **因果语言**：非实验设计使用因果推断措辞（中）。

### 表格与图

**表格**：APA 三线表（表头上方、表头下方、表底各一条横线），**无竖线**；编号加粗
（Table 1），标题在编号下一行且斜体；注释层级为通用注（Note.）→ 特定注（上标 a, b）→
显著性注；数字右对齐、小数点对齐。显著性星号：\**p* < .05，\*\**p* < .01，\*\*\**p* < .001。

**图**：按正文首次提及顺序编号；每张图必须在正文被引用；**图注在图下方**（表注在上方）；
图必须不读正文也能看懂。图注格式固定：`Figure N`（加粗，独占一行）→ 描述性标题
（斜体，句首大写）→ `Note.` 开头的解释。字号：图标签与标题 10–12 pt（加粗/斜体）、
轴标签 8–10 pt、轴刻度与图例 8–9 pt、Note 8–9 pt。

**图类型选择**：类别+数值比大小 → 条形图（**不用饼图**）；连续变量看分布 → 直方图 /
箱线图 / 小提琴图；两个连续变量 → 散点图 + 回归线；时间序列 1–5 条 → 折线图，
> 5 条 → 分面小倍数图（不要意大利面条图）；相关矩阵 → 热力图；元分析 → 森林图 /
漏斗图。**少于 3 个数据点、单个百分比或均值、需要超过两句话解释的，不要画图。**

**配色**：连续/顺序数据用 Viridis（8 色：`#440154`、`#46327E`、`#365C8D`、`#277F8E`、
`#1FA187`、`#4AC16D`、`#9FDA3A`、`#FDE725`）；色盲关键场景用 Cividis；分类对比用
Tol 定性板（`#0077BB` 蓝、`#33BBEE` 青、`#009988` 绿松、`#EE7733` 橙、`#CC3311` 红、
`#EE3377` 品红、`#BBBBBB` 灰、`#000000` 黑，最多 8 类）；发散用蓝-红
（`#2166AC` ↔ `#F7F7F7` ↔ `#B2182B`）。**绝不只靠颜色区分**——必须配形状、图案或标签；
非文字元素最小对比度 3:1；灰度打印仍要能区分组别。

**绝不做**：饼图、3D 图、双 y 轴（暗示虚假相关，拆成两个子图）、彩虹色图、未标注的
截断 y 轴、缺误差棒、装饰性 chartjunk。

**落盘规格**：分辨率 300 dpi；默认画布 6.9 × 4.5 in（散点 6.9 × 5.5、森林图 6.9 × 4.0、

## 六、投稿前自审：完整性与诚信

提交和修订完成后各跑一遍，**第二次要从零重跑，不能靠第一次的结论**。

### 引用与主张核对

1. **抽取 claim 并登记**：把定量/事实性主张找出来——数值型（百分比、计数、效应量、
   *p* 值）、类别断言（"X 是最大的…"）、趋势断言（"上升/下降/稳定"）、因果断言
   （"X 导致 Y"）。每条给稳定 ID，记录精确文本跨度、被引来源、所在章节。
   **不要把这一步说成"机械完整"**——语义抽取覆盖率本质上无法机器检测，报告里要写明。
2. **定位来源**：找到被引文献中支持该主张的**具体段落**。**不要 follow 一个 URL 或
   DOI 就假定它支持该主张**；必须真的读到那段文字。付费墙后 → 标 `UNVERIFIABLE_ACCESS`。
3. **比对**：逐项核对精确数字、日期范围、人群描述、方法描述，标记任何不一致。
4. **判定五级**：

| 判定 | 定义 | 严重度 |
|---|---|---|
| `VERIFIED` | 与来源精确一致或在舍入容差内 | 无 |
| `MINOR_DISTORTION` | 转述来源但语义保留（"约 15%" vs 源 "15.2%"） | Minor |
| `MAJOR_DISTORTION` | 过度简化、夸大或歪曲来源 | Serious |
| `UNVERIFIABLE` | **来源中根本不含所声称的信息** | Serious |
| `UNVERIFIABLE_ACCESS` | 来源存在但全文不可得 | Medium |

**通过标准：零 `MAJOR_DISTORTION` 且零 `UNVERIFIABLE`**。只有 `MINOR_DISTORTION`
和/或 `UNVERIFIABLE_ACCESS` 时是通过但有注记；`UNVERIFIABLE_ACCESS` 记录但不阻断。

### 新颖性主张的特殊处理

"我们是第一个…"、"此前没有工作…"这类主张断言的是**文献的不存在**，无法用引文核对。
只能对有检索边界的措辞做分类：措辞限定在检索范围内（"据我们所知，基于对[数据库]、
覆盖[时间范围]、截至[检索日期]的检索…"）**且**点名的数据库与日期范围与文档化的检索
策略完全一致 **且** 检索执行日期已记录 **且** 已承认最近的先前工作——才算
`SUPPORTED_WITHIN_SEARCH`。绝对化措辞、边界与检索策略不符、或没记录检索执行日期，
一律 `UNRESOLVED`。**永远不要给出"全局已核实"的新颖性结论**——有检索边界的主张只
在它的检索范围内被验证。

### 原创性

段落级检查：每段抽 1–2 句**特征句**（优先含具体数据、专有名词、独有论点的句子，
避开"This study aims to…"这类套话），用 8–12 个连续词加引号做精确检索，再用不加引号
的关键词检索捕捉改写版本，看前 5–10 条结果。分级：`ORIGINAL` /
`COMMON_KNOWLEDGE`（多来源以不同方式表述同一事实）/ `PARAPHRASE`（语义同、措辞显著
不同，**且有引用**）/ `CLOSE_MATCH`（句式近乎相同，只做同义词替换）/ `VERBATIM`
（**20 个以上连续相同词且无引号**）。

抽样率下限：投稿前 ≥ 30% 的正文段落，终检 ≥ 50%；优先查文献综述、背景、讨论等高风险
章节，每个主要章节至少抽 1 段；修订阶段新增或实质修改的段落**100% 检查**。

自引判定：引用先前工作并用新语言重述 → 合法；**引用但大段逐字照抄 → 自抄袭，即使
有引用也不可接受**；与先前工作高度相似却不引用 → 自抄袭；用先前工作的数据重新分析
→ 合法但必须明确说明；方法学标准化描述复用 → 灰色地带，建议引用先前工作。

后果分级：`CRITICAL`（Verbatim 或伪造引用）→ 立即失败，最高优先级整改；
`SERIOUS` → 失败，必须修复并复验；`MODERATE`（1–2 处 CLOSE_MATCH）→ 失败，必须修复；
`MINOR`（套话过多）→ 不影响通过。

**能力边界要在报告里写明**：这类检索式筛查只能比对公开可得的文献，无法检索付费墙
全文库，无法计算精确重合率，也检测不了跨语言翻译式抄袭。**它不是查重软件**，
正式投稿前建议用户用专业工具做完整查重。

### AI 参与研究最容易出的七类问题

这七类的共同危险在于：**它们读起来和称职的工作一模一样**。含幻觉结果的论文与含真实
结果的论文读起来一样；描述从未跑过的实验的方法章节与忠实叙述读起来一样。

1. **实现 bug 通过了 AI 自审**——off-by-one、用错变量、静默除零、类型强转、flag 写错，
   产出"数值上看着合理但科学上错误"的结果，然后被直接写进论文。检测：每个数值结果
   是否有产生它的已保存日志/脚本运行，**退出码是否为 0、warning 是否为 0**？没有日志
   就标出来。效应量是否**可疑地圆整**（恰好 0.5、恰好 2 倍基线、跨 run 方差恰好为 0）？
   误差棒在各条件间是否真的变化，还是可疑地完全相同？
2. **幻觉引用**——不存在的文献、年份/期刊/作者写错、或归因了它并不包含的发现。
   **每条引用都必须通过 DOI 或检索核实**，可用标题模糊匹配做批量校验，伪造的 DOI
   是最容易被漏掉的一类。
3. **幻觉实验结果**——结果不对应任何真实运行。"我们观察到 12% 提升"而没有任何一次
   运行产生过 12%。检测：每个"提升 X%/降低 Y%"的主张，作者是否持有据以计算的原始
   数字？论文里的表格是否对得上一个能指认的 CSV / 日志？说"跑了 N 个种子"是否
   **真的有 N 个 run 目录**？
4. **捷径依赖**——结果是真的，但模型是靠伪特征而非预期机制达成的（靠背景色而不是
   数字形状拿到 99% 准确率）。检测：是否有受控消融排除了最明显的捷径特征？
   "消融研究"消的真是所声称的机制，还是只动了附带超参？baseline 是否强到战胜它必须
   依赖所提机制？
5. **把实现 bug 重新包装成新发现**——pipeline 产出的异常其实由 bug 造成，写作阶段却把
   它包装成"我们意外地发现 X 在 Y 条件下行为异常"。**这种论文比无 bug 版本更有意思，
   所以更危险。** 检测：稿子里有没有 "surprisingly" / "unexpectedly" /
   "contrary to our hypothesis"？对每个这种主张，是否有文献本应预测相反结果？
   **没有文献预测相反，就不是惊喜，可能是 bug。** 这个异常出现在第一次运行，还是
   多轮 debug 之后才出现？首跑即惊喜，高风险。
6. **方法学编造**——方法章节描述了实际并未运行的实验、超参、数据集或流程。检测：
   方法里每个数字（学习率、批大小、轮数、数据量、划分比例）是否都出现在真实 run
   config 里？方法是否描述了代码里指不出来的预处理步骤？是否在实际未运行的地方用了
   过去时？**这要求把真实 run config 作为核对输入，而不只是论文文本。**
7. **早期阶段的框架锁定**——研究问题框定、方法学选择、超参方向的错误承诺，后续阶段
   因为结构上处于其下游而无法回退。论文执行得很好，但回答的是**错误的问题**。
   检测：如果带着现在所知回到最初，会不会改研究问题或方法？讨论里有没有 "in hindsight"
   / "we realized later"？**被触发时要提供回到起点的选项，而不是继续往下走。**

处理方式：每种模式给出 `CLEAR`（有证据排除，简要记录证据）/ `SUSPECTED`（一个或多个
检测问题给出令人担忧的答案，必须上呈用户）/ `INSUFFICIENT EVIDENCE`（没有用户输入
无法排除或确认）。**任一模式为 SUSPECTED 就阻断**；模式 1、3、5、6 为
INSUFFICIENT EVIDENCE 也阻断（它们需要用户提供日志才能排除，不得静默跳过）。
用户可选：确认为真并回头修、**带理由地显式推翻**（理由记入过程记录）、或修订该段后重跑。
终检时同一模式仍为 SUSPECTED 则再次阻断，**再多的修订轮次也不能跳过这一条**。

### 必备声明（每篇论文都要有）

- **作者贡献**：CRediT 的 14 个角色——Conceptualization、Data Curation、Formal
  Analysis、Funding Acquisition、Investigation、Methodology、Project Administration、
  Resources、Software、Supervision、Validation、Visualization、Writing – Original
  Draft、Writing – Review & Editing。每位作者可承担多个角色，每个角色可由多位作者承担。
- **数据可用性声明**、**伦理声明**（涉及人类被试或敏感数据时）、**利益冲突声明**、
  **资助致谢**、**AI 使用披露**（按目标期刊的要求写）。
- **局限一节**，显式讨论研究局限。

## 七、收到审稿意见之后

### 第一步：把意见变成可追踪的清单

审稿意见格式五花八门（邮件正文、PDF 粘贴、编号列表、自由段落、多位审稿人混在一块）。
按以下优先级切分：显式的审稿人标签（"Reviewer 1:"、"R1:"）→ 编号列表 → 项目符号 →
空行分隔的段落 → 话题切换。每条提取：审稿人 ID（R1/R2/R3/DA/编辑/未知）、
**原文逐字保留**、一句话摘要、语气。然后：

- 分类：Major（影响核心论证、方法或结论）/ Minor（影响质量或完整性但不影响核心效度）/
  Editorial（语法、措辞、格式、错别字）/ Positive（表扬，无需行动，在答复信里致谢）。
  分类信号："I strongly recommend…"、"fundamental flaw" → Major；"It would be
  helpful to…"、"Consider adding…"、"A minor point" → Minor。
- **映射到章节**：标题/摘要、引言、文献综述、方法、结果、讨论、结论、参考文献、通用。
- **抽取承诺**：每条意见里隐含的具体交付物（"补充 X 实验"、"澄清 Y"、"加一条引用"）。
  一条意见含多个要求时拆成多条承诺——复合要求不许合并成一条。写法很笼统的
  （"needs more work"）标 `NEEDS_CLARIFICATION`，问用户他认为审稿人指的是什么。
- **一条都不许漏**。解析总数必须 ≥ 输入中可识别的意见总数。同一意见被多位审稿人
  提到的合并为一条并注明"Raised by R1, R2"。
- 意见互相对立时**标出矛盾并保留双方立场**，不要替用户排序谁更重要。

**把"严重度"和"必须做/建议做"分开记录**，不要从一个推出另一个。严重度照抄审稿人给
的级别；"必须修改/建议修改/可考虑"来自编辑决定信的显式措辞或由用户确认，**不要从
严重度或审稿人人数推断**。

### 第二步：判断哪些该接受、哪些该顶回去

对每条 Major 意见，走四层：

1. **理解层**——审稿人的核心关切是什么？是方法、理论还是表达？
2. **判断层**——你同意吗？同意 → 怎么改；部分同意 → 哪部分同意、不同意的依据是什么；
   不同意 → 你的反驳论据是什么，能否用文献或数据支持？
3. **策略层**——答复信里怎么写？接受修改 → 具体说改了哪里；部分接受 → 说明接受了
   哪些 + 不接受的完整理由；拒绝 → 给充分的学术理由（文献、数据、方法学论证）。
4. **风险层**——拒绝这条建议，审稿人可能怎么反应？值不值得冒这个风险？

**不要默认"全部接受"**。真实审稿意见不总是对的，有些基于误读或学派偏见。但反过来，
**也不要谄媚式地全盘照收又不要对抗式地全盘拒绝**——两个方向都要给证据。

**修改范围纪律**：只回应审稿意见，不要顺手"改进"论文——加没被要求的章节、分析、
讨论属于范围蔓延，需要用户明确同意。同时，拒绝某条建议**不授予任何修改权**：
不做的条目就保持原样。

### 第三步：写答复信（R → A → C 格式）

每一段：**引用审稿人原话** → `**Author Response**` → `**Changes Made**`。

开头写 300–500 词的修改总结（主要改动、结构调整、字数变化、新增的分析/数据/文献）。
然后按审稿人分节。每节顺序：致谢审稿人指出的优点（**只有审稿人真的写了优点才写这一
段**，没有就跳过，不要编造）→ 逐条弱点（**每一条缺陷都要有一条对应的答复，数量不设
上限，不许因为"模板里只留了 4 条"就丢掉**）→ 逐条问题 → 次要问题用表格
（`# | Reviewer Comment | Action Taken | Location`）。

然后是"Required Revisions"表（`# | 要求 | 状态 | 答复摘要 | 位置`）和"Suggested
Revisions"表（状态为 Adopted / Not Adopted + 理由），最后是逐页改动对照表
（原稿页码 | 修改稿页码 | 章节 | 改动描述）和字数变化。

**好答复的特征**：直接（不回避问题）、具体（指出确切的改动位置和内容）、
有据（不同意时给文献或数据）、有礼（即使不同意也致谢）、完整（没有一条被落下）。
**坏答复**：敷衍（只写"已修改"却不说改了什么）、回避、防御（"审稿人误读了本文"
却不说为什么）、过度承诺（承认所有问题但不给方案）、**改动没标位置让审稿人找不到**。

**正确的不一致方式**（示范）：

> 审稿人建议用方法 X 代替方法 Y。
> 答复：感谢建议。我们选择 Y 的理由是：(1) 处理[某类]数据时 Y 表现更好（Smith
> et al., 2023）；(2) 本研究设计不满足 X 的[某条]假定；(3) 不过我们已在附录 B 中
> 补做了 X 的稳健性检验，结果一致。
> 改动：新增附录 B（pp.25–26），并在方法节（p.9 第 3 段）补充了选择 Y 的理由。

### 第四步：自查（这一步最容易被跳过）

1. **逐条对照**：原始意见清单与答复信一一比对——每条都有答复吗（完整性）？
   答复与实际改动一致吗（一致性）？**声称"已修改"的地方真的改了吗（真实性）？**
2. 修订期间新增的引用要重新走一遍引用核实。
3. 不重评论文质量（那是人类审稿人的事）、不出具新的编辑决定、不提新的修改要求——
   自查只做完整性/一致性/真实性的核对。

### 修订复审怎么判

修订完成后再看一遍每一条，判定分五级：

| 判定 | 含义 |
|---|---|
| `FULLY_ADDRESSED` | 修改稿里存在满足预设标准的**具体证据**（不是"作者说改了"） |
| `PARTIALLY_ADDRESSED` | 满足了一部分，**必须写明还缺什么**，以及剩余部分的级别 |
| `NOT_ADDRESSED` | 所需证据缺失 |
| `MADE_WORSE` | 修订让这一条相比原稿变差了 |
| `CANNOT_VERIFY` | 无法核验——按**保守原则**处理，等同于未解决 |

**核验的对象是修改稿里的证据，不是答复信里的声明。** 答复信只能告诉你"去哪里看"，
判定成立与否取决于稿件本身。作者声称改了但稿件里找不到对应证据的，判定不成立。
"应该出现改动的位置"只是导航假设——**改在别处但确实满足标准，同样算数；在预期位置
做装饰性修改想蒙混过关，不算**。

判定结果到决定的推导（先匹配先赢）：

- 任一"必须修改"项为 `MADE_WORSE` 且驱动发现的严重度为 Critical，或新问题中归因为
  "修订引入"的 Critical → **大修 + 建议考虑放弃**
- "必须修改"项中 ≥ 50% 落在 `NOT_ADDRESSED` / `MADE_WORSE` → **大修 + 建议考虑放弃**
- 任一"必须修改"项落在 `NOT_ADDRESSED` / `MADE_WORSE` / `CANNOT_VERIFY`，
  或有归因为"修订引入"的 Major 新问题 → **大修**
- 任一"必须修改"项 `PARTIALLY_ADDRESSED` 且残留部分仍属"必须修改"级别 → **大修**
- 任一"必须修改"项 `PARTIALLY_ADDRESSED` 但残留降级，或"建议修改"项的完成率 < 80%，
  或任一"建议修改"项 `MADE_WORSE` → **小修**
- 其余情形（所有"必须修改"项完全解决、"建议修改"完成率 ≥ 80%） → **接受**

新发现的问题要区分归因：**由本次修订引入的（regression）可以影响决定；原稿里就存在
只是第一轮漏掉的（previously_missed）只报告、不影响决定**——否则等于不断移动球门。
原稿缺失导致无法判断来源的，按"漏掉"处理并标出来，**绝不要静默升级成"修订引入"**。

**核验时不要看答复信再判定**。答复信是为说服核验者而写的文档，先读它会让判定锚定
在作者的叙述上。正确顺序是：先写下"什么算已解决"的标准 → 再看修改稿给判定 →
最后才看答复信，**只允许它告诉你"去哪里看"**。

### 轮次与期限

| 轮次 | 期望 | 处理 |
|---|---|---|
| R1 | 回应全部意见 | 送复审或由责任编辑审 |
| R2 | 回应残留问题 | 通常由责任编辑做最终决定 |
| R3 | 极少见，通常只处理格式 | 责任编辑做最终决定 |

小修时限 2–4 周，大修 6–8 周。修订完成率不是靠"作者解释得多好"来算的——**作者对
未修改条目的解释会被记录，但不计入完成率**。

## 八、常见坑

| 现象 | 原因 | 避免方式 |
|---|---|---|
| 写到一半发现结构不对，要重写 | 先动笔后想结构 | 先按研究问题性质选结构，再写 |
| 引言被批"铺垫太长" | 从"自古以来"讲起 | 从能显出利害关系的最窄处切入 |
| 空缺句被批不可验证 | 写了"没有研究做过 X" | 改成带数据库、时间、设计范围的检索边界说法 |
| 审稿人说"论证跳跃" | 结论超出设计能支持的范围 | 非实验设计不用因果动词；结论强度与设计匹配 |
| 审稿人说"文献不全面" | 只列不综合，或漏了关键近作 | 按主题或张力组织，向空缺推进；点名最近的相关工作 |
| 语言被批"读起来像机器写的" | 句长均匀、过渡语套式化、每段结构一样、术语来回换 | 用清晰度测试给段落分级投入；承重段多改几稿 |
| 统计被批"报告不完整" | 只报 *p* 不报效应量与 CI | 按第五章的必报项逐条对照 |
| 数字前后矛盾 | 正文手敲、表格来自另一次运行 | 所有数字从同一份结果文件生成，正文表格同源 |
| 图看起来很业余 | 默认配色、有边框、无误差棒、缺单位 | 按第五章图表规范；300 dpi 同时出 PDF 与 PNG |
| 引用被查出对不上 | 引了但没核对来源实际说了什么 | 每条引用核对到具体段落，比对数字、日期、人群、方法描述 |
| 引用列表和正文对不上 | 中途删改没同步 | 定稿前跑一次"零引用孤儿"检查 |
| 答复信很客气但审稿人仍不满 | 只说"已修改"不说改在哪 | 每条给页码/段落定位；不接受的给完整学术理由 |
| 返修后又被指出新问题 | 修订引入了新缺陷 | 修订后自查：新增内容重走引用核实，改动前后做一致性核对 |
| 修订越改越乱 | 一次动太多地方 | 只回应审稿意见；范围外的"改进"先问用户 |
| 声称改了但复审找不到 | 只改了答复信没改稿件 | 提交前逐条回查："我说改了的地方，稿件里真的改了吗" |

**最重要的一条**：不要为了让结果好看而编造、修饰或"合理推测"任何数字与文献。
核不出来的东西就空着、标出来，让用户去补——这比一个看起来完整的假结果有价值得多。

## 九、交付物清单

一次完整走完，应该产出这些东西（按用户实际需要的阶段裁剪）：

| 阶段 | 交付物 | 要点 |
|---|---|---|
| 定骨架 | 论文配置记录 + 结构选型 + 逐章字数分配 | 结构选型要写明理由；用户确认后才进入写作 |
| 大纲 | 详细大纲 + 证据映射 | 每个论点对应哪些证据/文献 |
| 初稿 | 分章草稿（含标题、摘要、关键词） | 字数落在目标 ±10% 内 |
| 引用 | 引用核查报告 | 每条引用的核实状态、问题清单 |
| 摘要 | 摘要 + 关键词（中英各一份，独立撰写） | 长度与关键词数按类型表；两份要点一致 |
| 图表 | 可运行的出图代码 + 图文件（PDF + PNG 各一份） | 300 dpi；配色可访问；图注含图号、标题、Note |
| 自审 | 五席位评审报告 + 编辑决定 + 修改路线图 | 每条发现带证据锚点与严重度；魔鬼代言人的 CRITICAL 必须显式裁决 |
| 诚信核查 | 引用核实报告 + 主张-来源对照表 + 原创性筛查报告 + 七类失败模式清单 | 写明能力边界（不是查重软件、语义抽取覆盖率不可机器检测） |
| 返修 | 修订稿 + 逐条答复信 + 改动对照表 | 修订稿里的改动位置与答复信一一对应 |
| 复审 | 修订响应核对表 + 残留问题 + 新决定 | 逐条标 FULLY / PARTIALLY / NOT / MADE_WORSE / CANNOT_VERIFY |

文件命名固定下来（如 `figures/figure_01.pdf`、`reviews/round1_r1.md`、
`response_to_reviewers.md`），多轮修订之间才对得上，不会出现"改了三版不知道哪版最新"。
