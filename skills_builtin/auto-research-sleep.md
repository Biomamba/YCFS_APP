# 长任务无人值守编排

## 什么时候用这条技能

用户说「你先跑着」「开完会再说」，或任务要跑几十分钟以上、中间会断（上下文被压缩、
进程被杀、超时），要跑多样本 / 多组参数 / 多数据集，后面的步骤依赖前面的产物，
或者用户不在场、出错了没人点确认时，按这条走。

核心问题只有一个：**agent 怎么在无人看着时不被卡死、不跑偏，回来时能看懂发生了什么。**

---

## 一条红线：驱动 ≠ 认可

循环可以自由地**驱动**自己往前走 —— 排下一个配置、重跑失败的任务、砍掉卡住的分支；
但**不能认可**自己的成果 —— 不能自己宣布「这个结果对」「可以交付了」。判据是一条问句：

> **一个没有品味、只会机械判断的脚本，能不能回答这个问题？**
>
> 能 → **A 类门禁**（执行事实），agent 可以自己判。
> 不能，需要品味 / 正确性 / 领域判断 → **B 类门禁**（质量结论），必须换独立判定者。

| | A 类：执行 / 客观 | B 类：质量 / 正确性 |
|---|---|---|
| 长什么样 | 退出码 == 0；结果文件存在；N/N 任务跑完；日志无 NaN；迭代到上限 | 「结论被数据支持吗」「分析方法对吗」「够不够格交付」 |
| 谁来判 | agent 自己 | 独立一方：另一个模型的评审，或一个确定性验证器 |

三条推论：**跑了 100 轮不改变性质**（「N 个同族评审都同意」是相关性盲区，不是陪审团 ——
独立判定要的是**换族**，不是**加数量**）；**复合门禁要拆，不能取平均**（「可以交付了」=
`A：产物都生成了` + `A：检查脚本退出码 0` + `B：结果确实支持结论`，丢掉 B 只留 A 然后说
「这个循环安全」是典型的自欺）；**拿掉独立判定者之后循环还能自己停下来 → 它就是在自批**
—— 安全的循环设计成「拿不到外部结论就终止不了」，不靠提示词措辞。

### 落地：把「跑完」和「通过」拆成两个状态

**必须体现在状态文件里。** 阶段状态：

| 状态 | 含义 | 谁能写 | 性质 |
|---|---|---|---|
| `pending` / `running` / `failed` | 没开始 / 在跑 / 执行者报错 | 执行者 | — |
| `done` | 执行者把产物写完了 | 执行者 | 执行完整性（同族自评安全） |
| `accepted` | 独立判定者给了正面结论 | **只有 accept 能写**，且必须记判定者身份 + 可追溯凭据 id | 质量 / 正确性 |
| `skipped` | 本任务不适用 | 执行者 | 终态，配置决定而非质量结论 |

两条硬规则：**执行者绝不能对自己写的东西调 `accept`**（标 `done` 可以，宣布「通过」不行；
判定者与执行者同族时要大声警告）；**恢复时走到第一个「非终态」阶段**，终态 = {`accepted`,
`skipped`}，**不是**第一个非 `done` —— 一个自己觉得「做完了」但在交叉审核前崩掉的阶段，
恢复时会被**重新验证**，而一个 `done` 却始终未 `accepted` 的阶段，是结构上可见的「还没人验收」。
`accept` 记的凭据要是**可长期追溯的把手**（判定者会话/追踪 id，或验证器报告路径 + 校验和），
不是一句「已审」—— 过一周还得能查出是谁批的。

## 主流程

### 第 0 步：写一份可判定的契约

无人值守时，唯一能让 agent 不跑偏的就是一份**写下来的契约**（项目根 `contract.md`），
五件事：**要回答什么问题**（写成能判真假的断言，不是「分析一下这批数据」）；**数据是什么**
（输入文件、分组、样本数、预处理到哪一步）；**对照是什么**（baseline / 对照组，以及它来自
本机重跑还是文献）；**怎么算成功**（具体到指标和阈值）；**不算数的边界**（哪些情况即使跑出来
也不能当结论，如「样本量 < 3 的分组不做统计」）。

契约要**自包含**：不写「见上文」，不依赖只在某段对话里出现的信息。**恢复时只读契约，
不读全部历史** —— 把 12 个候选方案都塞进上下文会挤掉工作记忆、拉低输出质量；
全量报告只在「当前方向失败、要换下一个」时才读。

### 第 1 步：切阶段，落状态文件

切成**有序、边界清楚**的阶段，标准是每阶段结束有产物落盘、且它是下一阶段的输入。
状态文件（一个任务一个）`runs/<run_id>.json` 记 `phases`（名字/状态/产物/判定凭据）、
`gates`（门禁结果）、`meta`（起止时间、下一步）。只有五个动作：

```
start_run(root, run_id, phases)                    # 有序阶段清单
set_status(root, run_id, phase, running|done|failed, artifact=路径)
accept(root, run_id, phase, verdict_id, reviewer)  # 唯一能写 accepted 的入口
record_gate_result(root, run_id, gate, PASS|BLOCKED, reasons)
resume_point(root, run_id)                         # → 第一个非终态阶段，或 None
```

- `set_status` **只能**写 `running/done/failed`；**只有 `accept` 能写 `accepted`**，
  且要求非空的 `verdict_id` + `reviewer` —— 这条在代码层面强制，不靠自觉。
- **单写者契约**：一个 run 只有一个编排者在写。改状态走「读-改-写 + 文件锁 + 原子替换」，
  走神的恢复进程也写不坏；但**调度器不许故意双开一个 run**。
- 门禁结果单独记，六态：`PASS | WARN | FAIL | BLOCKED | ERROR | NOT_APPLICABLE`。
  **静默跳过不允许** —— 不适用写 `NOT_APPLICABLE`，跑挂了写 `ERROR`。

### 第 2 步：先冒烟跑

**铺开全部任务之前，先跑最小最快的那一个。** 冒烟验证的是「管道通了」不是「结果对」：
流程走完不报错；指标算出来且**存成可解析格式**（JSON / CSV），不是只在屏幕上打印过；
资源占用在预期内；产物落在约定位置和格式。冒烟不过就别往下铺 —— 铺开只是把同一个 bug 复制 N 份。

### 第 3 步：批量与波次

**≤ 5 个**直接顺序或并行起，每个一个日志文件；**≥ 10 个 / 多参数网格 / 有阶段依赖**用队列调度器。

- **清单（manifest）** 一个文件描述所有作业：工作目录、环境名、每个作业的 id 与参数、
  期望产出文件、可用资源位、最大并行数。**网格别手写几十条**，给参数列表 + 模板让工具展开 ——
  `N=[64,128,256] × n=[50K,150K,500K] × seed=[42,200,201]` → 36 个作业。
- **依赖**：`distill` 依赖 `train` 时，`train` 作业**全部到终态**前 `distill` 保持 `pending`。
  ⚠️「终态」包含 `stuck` —— 失败的 teacher 不挡 student 启动。所以**用依赖波次的结果前，
  先查 `stuck` 列表**，别以为依赖满足就等于输入齐了。
- **作业状态机**：

  ```
  pending → running → completed
                   ↘ failed_oom  → pending（延迟后重试，最多 N 次）
                   ↘ failed_other → stuck（要人看）
  残留会话（进程没了但会话还挂着） → failed_other → stuck
  ```

- **波次释放条件，四条全满足才能起下一波**：① 当前波所有进程已退出；② 没有残留悬挂会话；
  ③ 资源（显存/CPU/文件锁）降到阈值以下；④ 下一波的前置条件检查通过。
  **前置条件显式声明**并逐条检查，失败时说清**哪些作业被挡住、为什么**，不要静默跳过。
- 调度器要**幂等**（崩了重启从状态文件接着跑）、**每个状态变化立刻刷盘**、
  轮询作业状态（60 秒是起点）、**按期望产出判完成**（不看会话/进程状态）。
- 检测残留会话：会话还在但进程已退出 → 产出在就标 `completed` 并清理，不在就标 `failed_other`。
  检测资源耗尽：从**每个作业自己的日志**里匹配错误模式（显存/内存不足），标 `failed_oom`，
  杀会话，等延迟，找空闲资源，重新入队。重启恢复时对每个 `running` 作业：真活着就保留，
  不活就重新判定。

### 第 4 步：无人值守期的两层监控

| 层 | 回答的问题 | 频率 | 判什么 |
|---|---|---|---|
| 表面健康（看门狗） | 「它还活着吗？资源在用吗？」 | 持续，几十秒一次 | 会话存活 + 资源利用率 + 文件是否在长 |
| 深度检查 | 「跑出来的东西对吗？」 | 按需，十几分钟到一小时 | 日志解析、指标趋势、结果收集 |

看门狗状态码：`DEAD`（会话没了）、`IDLE`（长时间计算但利用率 < 5%）、`STALLED`（下载/拷贝
目标文件不增长）、`SLOW`（速度 < 1 MB/s）、`STALE`（内部循环的心跳文件超出窗口未更新）、
`MISSING`（宽限期后心跳文件仍缺）、`PENDING`（等首次写入）、`COMPLETED`，以及 `OK` / `ERROR`。

输出必须是**一行一个任务**的汇总文件（外加跨会话的告警日志），外部低频率轮询者能廉价读完成状态、
**不需要挂着一个会话**。新会话恢复的第一件事就是看告警日志 —— 你不在时发生的异常全在那里。
**看门狗只检测，绝不自动重启，绝不重跑任何判定类步骤**，恢复由人或调度器决定。

**心跳怎么写**：**每次迭代的第一个动作就刷新心跳文件**（重写或 `touch`），**抢在任何可能挂住的
工作之前** —— 这样 mtime 才代表「循环还活着」，而不是「上一轮跑完了」。`stale_after_seconds`
是**这个循环自己的容忍度**，设成**长于单次迭代最长耗时**（约 3 倍 tick 间隔），**绝不是**看门狗的
轮询间隔。循环结束要带终态 `status` 或主动注销自己。

**什么时候可以挂到外部定时器上**：判据是**它等的是不是「外部世界的一个事实」**（作业跑完了、
指标写进日志了、文件落地了）。是 → 可以挂；等的是「agent 自己产生的判断」→ 不能挂。

- ✅ 可以排：作业完成轮询、资源是否空出的轮询、日志异常检查、队列进度可见性、夜间心跳。
- ❌ 不能排：**已经有内部循环的东西**（重复的调度器会和它自己的调度打架 —— 错开的时钟 +
  波次转换 = 竞态）；**判定类步骤**（质量不会因为时间到了就变好，按钟表重跑判定、产物根本
  没变，纯烧钱还很吵）。

一句话：**排「等」，不排「判」。** 夜间心跳可以醒来、发现某阶段**停滞了**，然后**推它一把**
（解开卡住的步骤、重启掉线的作业）—— 这改变的是「什么时候 / 还要不要继续做」，不是「做得对不对」：
**心跳只能说「继续跑」，永远不能说「够好了」。**

### 第 5 步：回来后怎么恢复

新会话或上下文被压缩后，**按固定顺序读，不要重翻全部历史**：① 项目仪表盘的状态段（30 秒定位）
→ ② **契约文件**（当前任务的聚焦上下文，不是整份历史报告）→ ③ **发现日志的最近几条**
→ ④ 完整实验日志（**按需**，不要无脑读）→ ⑤ 状态里 `active_tasks` 非空就检查那些后台任务的
真实状态，重建监控。**不要在非切换任务时读全量候选/全集报告** —— 那是上下文污染。
仪表盘状态段：

```yaml
stage: 当前阶段
task: "当前任务的一句话描述"
contract: 契约文件路径
baseline: "对照组 acc=95.2"
active_tasks:
  - "样本 01-24 的比对（会话名、资源、检查命令各一行）"
last_updated: YYYY-MM-DD HH:mm
next: 下一步具体动作
```

**什么时候更新**：阶段切换、任务选定或更换、baseline 确认、长任务启动或结束、做出重大决策，
以及**用户说「记录一下」「保存」「开个新会话」「收工」时** —— 最后这条是在开新会话前持久化
状态的信号。

**陈旧状态检测**：读任何状态文件前先看 mtime，默认阈值 **24 小时**（单个技能可覆盖）。超了就
警告这条状态可能来自上一轮任务，问用户继续用还是重开；选重开就先写一份带时间戳的归档副本。

### 第 6 步：汇总与汇报

全部作业到终态（`completed` 或 `stuck`）后，**编排者自己**聚合状态写汇总，不要指望调度器。

```markdown
# 任务汇总：<名称>
**开始** / **结束** / **总墙钟时间**
**作业统计**：N 完成，M 重试后完成，K 卡住

## 分阶段
| 阶段 | 作业数 | 成功 | 重试 | 耗时 |

## 结果文件
- 具体清单（路径 + 一句话说明内容）

## 异常与未完成
- 每个 failed / stuck 的作业：卡在哪、试过什么、为什么停下

## 停止原因
超时 / 迭代上限 / 停滞 / 达成目标 —— 四选一写明白

## 下一步建议
```

报告里必须有的：**先给原始数字再给解释**；**和正确的对照比**（同一个配置下的 baseline，不能拿
另一个配置的数来比）；**还在跑的明确标出来**，不要混进已完成；**异常结果显式标出来**
（负的 delta、NaN、发散、和预期方向相反的）；多随机种子的**报均值 ± 标准差**并检查可复现性；
**可疑结果先看日志确认是不是真跑对了**再下结论。

汇报结构：核心故事 2-3 段 → 编号的断言（每条带数字和证据来源）→ 实验设置（数据 / 对照 / 硬件）
→ 每个实验一张表 + 一句解释 → 图清单 → **已知弱点** → 下一步。**已知弱点必须自己先写出来**
—— 不写弱点的汇报，读者默认它不可信。

## 判据与阈值

| 项 | 默认值 | 什么时候改 |
|---|---|---|
| 队列轮询间隔 | 60 秒 | 作业普遍很长时放宽到 120-300 秒 |
| 资源空闲阈值 | 已用 < 500 MiB 才算空 | 共享机器调高；独占紧凑打包调低 |
| 作业重试延迟 / 上限 | 120 秒 / 3 次 | 资源紧张时调高延迟；超过上限标 `stuck`，**不要无限重试** |
| 单次尝试的修复预算 | 2 次补丁 + 2 次干净重写（共 4 次） | 不要加。两次重写同样失败 = 问题在契约或环境 |
| 迭代总上限 / 连续无改进 | 50 次 / 10 次 | 空间大时调高上限（必须同时有超时）；小空间容忍调到 5 |
| 单次搜索墙钟超时 | 2 小时 | 按实际耗时设，**必须设**；冒烟/试点硬超时 3 小时 |
| 多轮评审轮次上限 | 4 轮（评审循环）/ 2 轮（纯写作改进）/ 5 轮（方法精炼） | 收益递减明显，别加轮次 |
| 状态文件陈旧阈值 | 24 小时 | 长期项目调长 |
| 内部循环心跳窗口 | ≈ 3 倍 tick 间隔，且 > 单次迭代最长耗时 | **绝不能设成轮询间隔** |
| 建产物索引 | 产物 > 15 个才建 | 少于这个数，索引本身就是一份要同步的重复品 |

### 停滞检测与强制转向

无人值守的循环会空转：每次迭代都试上一个的近似变体，收益递减。**机械地**检测它，然后强制
**结构性**的改变，而不是把同一套参数调得更狠。

- **数数，不要凭感觉。** 每次迭代记录**新增发现数** —— 具体加进去的条目（新证据、被证伪的
  假设、新候选方向），**不是**主观的「有价值的成果」。连续零新增累积 `stale_count`，记在
  **旁路账本**（append-only，如 `runs/<run_id>.iterations.jsonl`），**不要碰主状态文件的
  done/accepted 状态机**。
- **阶梯**：`stale_count >= 2` → **换结构，不换参数**（改框架 / 目标 / 数据 / 表示），且选一个
  和已试过的都不同的方向；`stale_count >= 4` → **升级给人**，不要继续盲目地推。
- 重新生成候选前先读已试过的方向清单，**拒绝和已试过的太接近的候选**。

这是纯 A 类信号 —— 数条目、改方向，从不判质量。它只说「继续 / 换方向」，从不说「够好了」。

### 坏尝试要能重启，不只是打补丁

上面转向的是**方向**，这一节是它下面一层 —— 还在跑的循环里**单次实现/调试尝试**反复失败。

- **推倒重写是「再打一个补丁」的同级选项，不是最后手段。** 同一个失败上 1-2 次针对性补丁
  失败后，**从契约/计划干净重写那一块**通常比在两层错补丁上再打第三层更便宜可靠 ——
  补丁堆出来的代码考古是尝试烂掉的主要方式。
- **只有契约本身可疑时才升级给人** —— 计划/规格缺失、含糊、或看起来是错的。「跑不起来」是
  执行者的问题；「计划可能是错的」才是人的问题；把「构建坏了」上报给人是**错误的路由**。
- **硬边界 —— 重启允许删什么：** 只能删**当前尝试自己的**代码/脚手架（它写的脚本、它生成的
  配置、它的构建产物）。**永远不能删**：契约/计划、进度账本（任务清单、迭代账本、状态文件、
  审计追踪）、已收集的数据、已完成的结果 —— 重启是**从这些文件重建代码**。**不确定一个路径是
  「尝试」还是「状态」时，当作状态保留。** 重启也消耗重试预算。
- 重写后**重新验证指标可比性**：用新解析脚本重新解析一个**已完成**迭代的原始输出，确认它能
  复现账本里那一行；对不上就修解析器，或重新解析并标记所有受影响的行 —— **绝不允许一份账本里
  混着两套解析语义。**

外部数据源的长任务另加两条：监控**目标路径的大小增长**而不是只看进程活着；用完即弃的远端资源
（按小时计费的机器/实例）**在任务完成后主动释放**，把「下载产物 → 下载日志 → 释放 → 报告费用」
做成固定动作 —— 无人值守最容易出的错就是「算完了但机器还开着」。

## 常见坑

**1. 把「自己觉得做完了」当成「已经验收」。** 恢复后跳过某阶段，但它从没被独立看过。
→ `done` / `accepted` 分开存，恢复走第一个**非终态**（不是第一个非 `done`）。

**2. 用外部定时器包一个已经有内部循环的东西。** 钱花了、产物没变，或两个调度器互相踩。
→ 有内部调度器的（队列、评审循环）**只用它的状态输出做可见性**，要排就排**它前面的外部等待**。

**3. 心跳在干活之后才写 / 看门狗自动重启。** 循环卡住了看门狗却显示正常；一个判定类步骤被
无声重跑三次，谁也不知道哪次算数。→ **每次迭代的第一个动作就刷新心跳**（窗口大于单次迭代最长
耗时）；看门狗**只写状态和告警**，重启由人或调度器决定。

**4. 依赖满足就当输入齐了。** 下游波次全崩在「输入文件不存在」——「前序阶段全部到终态」里的
终态**包含 `stuck`**。→ 用依赖波次的结果前**先查 `stuck` 列表**。

**5. 重试没有上限 / 无限打补丁。** → 重试上限 3 次，超界标 `stuck` 报给人；1-2 次补丁失败就
考虑干净重写，预算用尽就停下上报。**两次干净重写以同样方式失败 = 契约或环境有问题，要明说。**

**6. 只靠进程状态判完成 / 状态不刷盘 / 同一资源上重叠启动。** 写完了被当失败重跑；调度器一崩
进度全丢；新作业一起就 OOM。→ **按期望产出文件判完成**，**每个状态变化立刻写盘**，起新作业前
等资源降到阈值以下（显存默认 < 500 MiB）。

**7. 把操作噪声写进持久化的知识里。** **不要落盘这四类**：环境特定失败（「找不到某某模块」）、
瞬时错误（限流、OOM、连接被拒）、**否定能力的断言**（「某工具处理不了长文件」）、单次事件叙事
（「第 47 次运行在第 300 步炸了」）。**要落盘的是**修复方法 / 缺的依赖 / 正确的配置 / 从单次
事件提炼的**类级别**规则（如「学习率 > 3e-4 在这个模型上会发散」）。**记「怎么修」，不记
「X 做不到 Y」** —— 否则那句噪声会在以后每次会话里被当成事实引用。

**8. 断言引用了不存在的证据。** 汇报写着「准确率 73.2，见 results/eval.json」，文件不存在或
里面是 73.5。→ **每条「数值 + 来源」的断言先机械核对**：路径存在吗？值在文件里吗？数值用
**精确 token 匹配**（`73.2` 匹配 `73.20`，但 `73` **不**匹配 `73.5`）。⚠️ 预检通过只说明
**证据存在**，不说明**结论成立** —— 后者仍要独立判定者。

**9. 无人值守时结束在一个提问上。** 然后一整晚什么都没跑。→ **不要用提问结束回合**，常规歧义
自己定、动手做、把决定记一行日志。**「准备好了」就等于「执行」。** ⚠️ 但这条**不覆盖显式的
人为门禁** —— 真正需要签字的（目标缺失、发布/提交动作）照样停下等；拿不准一个门禁是不是显式的，
**当作显式处理**。

**10. 产物互相覆盖 / 汇总只写结论。** 第二次跑覆盖了第一次的结果；汇报里只有「分析完成」四个字。
→ **会覆盖的产物写两份**：带时间戳的永久历史（`名字_YYYYMMDD_HHmmss.md`）+ 固定名「最新副本」，
下游只读固定名那个（追加式文件、按轮次命名的文件、仪表盘、产物索引不打时间戳）；汇报先给原始
数字表再解释，区分「已完成」和「还在跑」，把失败/跳过的条目连同原因列出来，写清停止原因，
**已知弱点这一节不能省**。

## 交付物清单

| 文件 | 内容 |
|---|---|
| 仪表盘状态段 | 当前阶段、任务、活跃任务、下一步、最后更新时间 |
| `contract.md` | 契约：问题、数据、对照、成功判据、不算数的边界 |
| `plan/EXPERIMENT_PLAN.md` | 跑什么：断言 → 实验块 → 里程碑（冒烟 → 对照 → 主体 → 消融）→ 预算 |
| `plan/TASK_TRACKER.md` | 执行清单：run id、状态、一句话备注 |
| `plan/EXPERIMENT_LOG.md` | 完整记录：设置、结果表、结论、复现命令。**成功失败都要记**，每实验结束**立刻**写 |
| `findings.md` | 追加式发现日志：非预期现象、根因、关键决策 |
| `results/*.json` `*.csv` + `logs/` | 每个 run 一份结构化结果 + 一份独立日志 |
| `runs/<run_id>.json` / `.iterations.jsonl` | 阶段状态机（6 态）+ 门禁结果（6 态）/ 迭代账本（`stale_count`、`direction`） |
| `REPORT.md` | 汇总报告：分阶段表、结果文件清单、异常与未完成、停止原因、下一步，配主结果图 + 收敛曲线 |
| `MANIFEST.md` | 产物索引，**只在产物 > 15 个时才建**（时间戳 / 文件 / 阶段 / 描述） |

两条容易忽略但值钱的：**实验日志和任务清单是两份文件，受众不同** —— 清单是执行管理
（「还剩什么没跑」），实验日志是知识保存（「跑了什么、学到什么」），清单换任务时可重置，
日志是永久记录；**审计追踪留在项目本地**（每次独立评审一份，按 `run_id` + 轮次命名）
并加进版本控制的忽略列表 —— 它是过程证据，不是交付物。
