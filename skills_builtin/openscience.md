# 开放科学产出规范

这条技能管的是**产出**那一端：一次分析做完之后，别人（包括三个月后的你自己）能不能
复现它、能不能复用里面的数据与代码、能不能引用它。它不改你的科学问题，只改你把结果
交出去的方式。三条底线贯穿全文：

1. **目标先于运行** —— 什么数字算成功，跑之前写下来，跑完不许改。
2. **来源可追** —— 报告里每一个数字都能指回一个原始输出文件或一条能重放的调用。
3. **不完整就说** —— 拿不到、跑不通、没核对的东西列出来，不留占位符，也不含糊过去。

## 什么时候用这条技能

- 分析结果要写进报告、论文，或要交给别人接手时；要复现别人（或自己上次）的一个数字、
  一张图时；要给数据、代码、结果挑选目录结构、命名、版本与许可时；稿件、数据集、报告
  投出去或归档之前做最后一遍核对时。

**不适用**：纯粹探索性的分析，结果只用来决定下一步做什么、不会离开当前会话 —— 那种
按普通探索流程跑就行。判据很简单：**这个数字会不会出现在别人要读的东西里**。

## 一、先冻结目标

复现是一次**测量**：跑之前定好什么算成功，跑完写清到底跑了什么。跑完再调整目标的，
不是复现。把下面这份记录写在 `reproduction/<name>/target.md`，**在任何执行之前**：

```markdown
Claim: <来源里的原句，照抄>          Source: <doi / arXiv id / 章节 / 表号>
Metric: <名称>, <方向>   Expected: <值 ± 不确定度或区间>   Tolerance: <值 + 为什么>
Data: <名称、版本、划分、过滤、许可与访问条件>   Conditions: <种子、预算、硬件>
Canonical path: <仓库、commit、命令>            Missing: <恢复不到的输入>
```

- 来源没给不确定度，就自己选一个容差并**写出理由**，不能省略这一格。
- **先跑原作者发布的路径**（他们的代码、config、checkpoint、数据）；只有那条路不可用
  或坏了才写替代实现，并在结果第一行注明「这是重实现」。
- 不许为了更接近论文而改超参、过滤条件或指标 —— 那是一个新实验，另行报告。
- 判定只能落在这五个词里，不许自造：

| 判定 | 含义 |
| --- | --- |
| reproduced | 走的是原始路径，且在容差内 |
| reproduced within tolerance | 差异可解释（硬件非确定性、版本漂移）且落在既定容差内 |
| partially reproduced | 部分主张或条件成立，其余不成立，逐条列出 |
| not reproduced | 原始路径确实跑通了，但数字在容差外 |
| untestable | 输入拿不到或路径坏到无法修，写清缺什么 |

不是复现而是**新研究**时，同一套纪律换个名字：采数据或开跑之前把假设写成可否证的形式，
每条都带一个「若它为假，会看到什么」的预测，以及预先指定的主要结局、分析和判定规则。
**至少写两条** —— 你的假设，加同一现象最强的竞争解释（混淆、伪影、更简单的机制）；
分不开这两者的还不算一个设计。设计清单里要有：设计类型（组间／组内／析因／交叉／消融
阶梯／剂量-反应）、随机化与区组方式、对照（阳性、阴性、载体／sham）、每个臂固定不变的
评估方式、n 及依据、主要结局与检验、多重比较校正、离群值与缺失值的处理规则。

⚠️ **事后补一个校验和只能证明「文件与结果一致」，不能证明「分析是预先注册的」**；
要声称预注册，必须有一份运行前写下、之后没被编辑过的设计清单。

## 二、目录与命名约定

```
data/raw/               原始数据：只读，永不覆盖
data/clean.parquet      清洗产物（由脚本生成，不是手工另存）
scripts/01_prepare.py   脚本：两位序号 + 动词
scripts/02_analyze.py
results/summary.csv     数字输出
figures/                图，与生成它的脚本同名并列
requirements.lock       环境锁定
run.log                 每条命令 + exit code + 耗时
reproduction/<name>/    target.md（跑之前）、report.md（跑之后）
```

- 脚本一律 `NN_动词.py`，入口参数用 `--in / --out / --seed` 这种名字：

```bash
python scripts/01_prepare.py --in data/raw.csv --out data/clean.parquet
python scripts/02_analyze.py --seed 0 --out results/
```

- **图的脚本必须跟图放在一起**（`figures/loss_curve.py` 挨着 `loss_curve.pdf`）：图还在、
  脚本没了，下次别人要你补一个种子重画时你补不出来。
- 新产物写到新目录，**已存在的输出永不覆盖**；原始日志与派生摘要分开放。
- 长跑用台账四件套：`study.md`、`ideas.md`、`results.tsv`、`lessons.md`，被否掉的运行
  也要留在里面 —— 它们是让留下来的结论诚实的那部分消融实验。一个想法只跑一次，要试变体
  就新开一条想法，不要在同一配置上反复重跑。

## 三、执行可复现性

一个只存在于终端滚屏里的数字，或者一个在「核多内存大」的机器上跑出来的数字，还不是
结果。下面几条挡掉的是分析「明明跑通了」之后最常见的两种死法：**没法重跑**，或者
**重跑出来不一样**。

1. **会活过 shell 提示符的步骤要脱离执行。** 超过几分钟的步骤用受管作业提交（声明
   名称、命令、工作目录、产物路径、断点路径）再等它，失败时读日志。不要在 shell 里写
   `sleep` 轮询 PID 或文件的循环 —— 被阻塞的 shell 会随会话一起被杀，作业记录不会，
   而且作业保留自己的日志和退出码。
2. **断点续跑。** 在自然边界（每轮、每块、每个输入文件）落盘进度，入口先查这个状态再
   开始，被打断后的重跑应该只做剩下的部分。断点按步骤命名（`chunk_0042.parquet`），
   不要按时间戳命名。
3. **种子与线程都要钉死。**

```python
import random, numpy as np, torch
random.seed(0); rng = np.random.default_rng(0); torch.manual_seed(0)
```

```bash
# 必须在 python 导入 numpy/torch 之前导出：BLAS 只在加载时读它们
export OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 NUMEXPR_NUM_THREADS=2
export PYTHONHASHSEED=0
```

   两个理由：线程数会改变归约的求和顺序，所以「逐位一致的重跑」需要固定线程数；而在
   2 核配额里张开 64 个 BLAS 线程只会互相踩。已在运行的 BLAS 用
   `threadpoolctl.threadpool_limits(n)` 兜住。Linux 上读 `len(os.sched_getaffinity(0))`
   而不是 `os.cpu_count()`，并从 `/sys/fs/cgroup/cpu.max` 与 `memory.max` 读真实配额。
   要 GPU 端完全确定性还要 `torch.use_deterministic_algorithms(True)` 和
   `CUBLAS_WORKSPACE_CONFIG=:4096:8`；接受了非确定性，就在报告里说明。
4. **大表流式读、显式声明 dtype。** `pd.read_csv(..., usecols=[...], dtype={...},
   chunksize=200_000)` 分块聚合；数组用 `np.load(path, mmap_mode="r")`；Parquet 用
   `pyarrow.parquet.ParquetFile(path).iter_batches(batch_size=...)`；惰性管线用
   `polars.scan_csv` / `scan_parquet`。推断出的 dtype 会跨块翻转（出现一个缺失值就把
   整型列变成浮点），显式 dtype 既让读取确定，通常还能把内存降好几倍。
5. **输出原子写。** 写到目标目录里的临时文件，flush 后 `os.fsync`，再 `os.replace` 换名；
   换名只在同一文件系统上原子，这就是临时文件必须放在目标旁边的原因。

```python
import os, tempfile

def write_atomic(path, data: bytes) -> None:
    fd, tmp = tempfile.mkstemp(dir=os.path.dirname(path) or ".", prefix=".tmp-")
    with os.fdopen(fd, "wb") as f:
        f.write(data); f.flush(); os.fsync(f.fileno())  # 只换名不保证字节落盘
    os.replace(tmp, path)
```

6. **对着将要重跑它的那台机器写，不是对着这台。** 写下目标环境的 CPU 数、内存、墙钟
   上限、有没有网络，并在这些限制下测一遍：`taskset -c 0-1`、`ulimit -v`、`timeout 30m`，
   或带 `--cpus/--memory` 的容器；再做一次断网运行确认没有任何下载。锁定依赖版本；
   目标离线时不要在运行时 `pip install` 或下模型；小资源直接随代码存放。
7. **每条命令记 exit code。** 脚本开头 `set -euo pipefail`；每个贡献了报告数字的命令都
   追加到 run log，带退出码和耗时：

```bash
timeout 30m taskset -c 0-1 python pipeline.py --seed 0 2>&1 | tee -a run.log
echo "pipeline exit=${PIPESTATUS[0]}" >> run.log
```

   「第九步的数字不对」最常见的解释，就是第三步静默失败了。
8. **交付前干净重跑。** 删掉派生输出或换一个全新目录，从原始输入到最终产物再跑一遍，
   和你即将报告的数字比对，并计时。超了预算那是要修的缺陷，不是一句脚注；只有运行以
   小时计才可跳过，且要明说。
9. **绝不留占位符。** 不许在交付物里留待填的值、不许在该出数字的地方写 `NaN`、不许先
   建空文件等着以后填。算不出来的值，就在它本该出现的位置写明为什么算不出来，报告里
   说同一件事。

交付时要能一句话回答「怎么重跑」：从仓库根目录依次跑 `01_prepare.py` → `02_analyze.py`，
并带上资源与环境说明（`约 X 分钟，N 核，Y GB 内存，不需要网络；环境 requirements.lock；
产物 results/summary.csv、figures/`）。

## 四、数据与元数据

### 4.1 每个输入都要有 provenance

报告里的数据来源表，列为：

| Source | Version / release | Access date | Rows in | Rows out | Filter | Checksum |
| --- | --- | --- | --- | --- | --- | --- |

「Rows in / Rows out」这一对是行数流：**每一步过滤后还剩多少条、为什么掉的**，必须能
连起来。少了这个，读者无法判断你的样本是他以为的那个样本。

### 4.2 标识符要认准

| 对象 | 形式 | 例子 |
| --- | --- | --- |
| 论文 | DOI 优先 | `10.1038/sdata.2016.18` |
| 预印本 | arXiv id | `2301.12345`（不带版本后缀，除非你要指的就是那一版） |
| 生物医学文献 | PMID / PMCID | `34567890` |
| 作者 | ORCID | `0000-0001-6187-6610` |
| 机构 | ROR | `https://ror.org/05a0ya142` |
| 期刊 | ISSN | `0028-0836` |
| 存档的数据/软件 | Zenodo 记录号 | **concept DOI 与 version DOI 不是一回事**：指向「这一版」还是「这个东西」要选对 |
| 组学提交 | BioStudies / 各库 accession | `S-BSST12345`、`E-MTAB-1234` |

跨库转换：Semantic Scholar 接受前缀 `DOI:`、`PMID:`、`ARXIV:`；OpenAlex 接受 `doi:`、
`pmid:`。一个库里查不到，通常**换成另一个标识符再试**比改写检索式更快。

### 4.3 数据版本与校验和

- 数据文件记：来源、版本或 release、访问日期、大小、行数、校验和、分析前做过的过滤；
  能固定成不可变版本的就固定（release tag / 存档记录号），不要引用一个「最新版」的会
  变动的地址。
- 拿到校验和时也要说清它证明什么：**校验和只能证明本地文件与记录一致，不证明来源、
  真实性或充分性**。
- 大数据集不要塞进交付包；给标识符、访问方式和获取脚本。

### 4.4 格式选择

- 表格：分析中间态用 Parquet（有 schema、列式、读得快），不要用反复另存的 CSV。数组：
  NumPy 用 `.npy/.npz`；需要分块/压缩/并行写用 Zarr；层次化、需自描述的用 HDF5 —— 写
  的时候把维度含义、单位、坐标轴写进属性，不要留一个裸数组。
- 图像：科学图像不要用 JPEG（有损、会造出数据里没有的结构）。

### 4.5 目录骨架与数据集级元数据

领域里有现成的元数据标准就**照它的骨架放**，不要自己发明一套。以神经影像 BIDS 为例，
可迁移的规则是：

- 根下固定几个功能目录：`code/ docs/ derivatives/ logs/ phenotype/ sourcedata/
  stimuli/`，加上每个受试者一个 `sub-<label>/[ses-<label>/]<datatype>/`；用 `ses-` 就要
  对**所有**受试者都用。
- **标签有语法**：`<label>` 只允许字母数字、不加前导零（`run-` 例外）；`<index>` 零填充
  到同一数据集内等宽（`run-01`、`run-02`）；实体按固定顺序排列，顺序错了名字就不再是
  合法标识符。
- **数据集级描述文件**：`Name` 与 `BIDSVersion` 必填，`License`、`DatasetType`、
  `GeneratedBy`、`SourceDatasets` 建议填。有 `CITATION.cff` 时 `Authors` **必须删掉**，
  否则两处信息不一致；`DatasetDOI` 必须是合法 URI（裸 DOI 已废弃）。派生数据的每个子
  目录要有自己的描述文件，`DatasetType` 写 `"derivative"`，`GeneratedBy`（`Name`、
  `Version`、`CodeURL`）必填。
- **表格卫生**：制表符分隔、UTF-8、Unix 换行（空格、BOM、CRLF 是校验失败第一大户）。
  **缺失值统一写 `n/a`**，不要写 `NA`、`NaN` 或留空。每张表配一份数据字典说明列的含义、
  单位与取值等级；主键必须与目录结构一一对应。**元数据继承**：文件级 > 受试者级 >
  数据集级，只写与上层不同的部分，不要到处复制常量。
- 有校验器就用（如 `bids-validator`），**每次转换或改动之后都跑一遍** —— 它报的通常不是
  代码 bug 而是命名或元数据问题；忽略规则写在根目录的 `.bidsignore`。版本要记在**数据
  旁边**：数据集版本在描述文件里，派生产物在 `GeneratedBy.Version` 里，每个处理步骤在
  它自己的 `versions.yml` 里。

### 4.6 数据版本控制与「复现检查」命令

数据太大进不了 Git 时，用「结构进 Git、内容进 annex」的路子（DataLad 的做法）。推论要
记住：**克隆下来会有完整历史和完整文件清单，但几乎没有数据本身** —— **「文件存在」不
等于「内容在本地」**，读之前先取内容；一个文件报告为空、被截断、解不开，而磁盘上只有
几百字节，那多半是个指针。

推荐的分析型布局（YODA）：`code/` 与 `README.md`、`CHANGELOG.md` 由 Git 直接跟踪、不进
annex，这样在**没取任何数据**的克隆里脚本依然可读可 diff；输入数据作为子数据集挂在
`inputs/` 下，不要把别人的仓库随手放在里面。三句话原则：**一件事一个数据集；记下数据
从哪来；记下对它做了什么。** 每次运行都留一条运行记录：

```bash
datalad run -m "extract brain mask" --input "sub-01/anat/sub-01_T1w.nii.gz" \
  --output "derivatives/sub-01_brain.nii.gz" "bet {inputs} {outputs} -m"
```

记录写在 commit message 的 JSON 块里，**不要手工编辑那个块**，重跑工具靠解析它。两条
不变量：没有产生任何变化的运行不产生 commit；数据集 dirty 时运行被拒绝 ——
**建立在未知起始状态上的记录，什么也证明不了。**

**可复现性检查就一条命令**：把历史重放到新分支，再与原分支 diff。

```bash
datalad rerun -b repro-check --since <首次分析提交> HEAD
git diff main repro-check -- results/     # 输出为空 = 复现成功
```

重放落在别处，diff 直接回答「输出是不是一模一样」；想先看不跑加 `--report`，只想导出
命令加 `--script`。软件环境也作为内容版本化（把镜像注册进数据集再跑，provenance 就指向
一个具体镜像而不是某个可能被重推过的 tag）。

### 4.7 本体与受控词表：ID 一定要现查现验

**绝不凭记忆写本体 ID，也绝不接受未经检查的 ID。** 经典反例：`UBERON:0002108` 是小肠
而不是肝 —— 形式合法、本体也对，元数据却静默地错了。自检状态分三档：**fail**
（`not_found`、`obsolete` 要给后继词、`label_mismatch`、`wrong_ontology`、
`wrong_branch`、`malformed_curie`）；**warn**（`matched_synonym`、`imported_only`、
`not_a_class`，严格模式把 warn 提升为 fail，可以拿它当元数据文件的准入门禁）；
**未解析（unresolved）是一个正确的输出**，不是失败：保留原始字符串、空 ID 和原因。

按这个顺序判：本体内**精确标签**命中 → 接受；**精确同义词**命中 → 接受，但**写本体的
主标签而不是同义词**（这样元数据才能跟本体 release 干净地 diff）；精确命中但本体不对 →
通常是源列的分类错误，**改列，不要硬凑匹配**（组织字段里出现 `hepatocyte`）；只命中
partial → 不要静默接受，归一化后重试，或把候选给人看，或标未解析；什么都没命中 → 标
未解析并说明。归一化只折叠大小写和空白，可以去掉来源限定词（`liver (donor)`）、展开
实验室简写（`PBMC` → `peripheral blood mononuclear cell`）、反转倒装短语
（`ventricle, left` → `left ventricle`）、统一英式/美式、去掉物种前缀（物种单独放分类学
字段）；**不要**擅自去掉连字符、希腊字母、数字或大写的基因符号。**报告要给 ID + 标签 +
匹配方式** —— 一列光秃秃的 ID 没法复核。概念确实不存在就向本体 tracker 提新术语请求
（带定义和文献），**不要自造一个 ID**。

### 4.8 流程与管线的复现

- **固定一切**：管线 revision、引擎版本、容器 tag。**不要用 `latest` 跑你要发表的东西。**
- 每个处理模块输出自己的版本清单（`versions.yml`），版本记在产物旁边；一个进程一个
  容器或环境，**不要依赖宿主机上装了什么**。
- 有一条很好用的判据：**任何「改了它就会改变结果」的值，都必须是真正的输入通道，不能
  是靠配置注入的隐式开关。**
- 样本身份要贯穿整条管线传递（用带 id 的元数据映射），不要在中途丢掉。
- 要进快照测试的是稳定量：文件校验和、版本清单、清单长度。**绝对路径和时间戳不要进
  快照**，它们每次都变。

## 五、统计与设计

### 5.1 由设计决定检验，不是由 p 值决定

- **先看设计**：同一批单位测两次（前后、配对、同样本两种方法）是配对 —— 用 `ttest_rel`、
  `wilcoxon`。独立组用 `ttest_ind(a, b, equal_var=False)`（Welch；只有等方差是设计事实
  时才用 Student 并说明）。三组以上用 `f_oneway` / `kruskal`；区组内重复测量用
  `friedmanchisquare`。
- **有序分类要用趋势检验，不是通用检验。** 剂量、分级、分期、暴露水平：连续或有序结局
  用 Jonckheere-Terpstra，二分类结局用 Cochran-Armitage（Python
  `statsmodels.stats.contingency_tables.Table(counts).test_ordinal_association()`，R
  `prop.trend.test`、`DescTools::CochranArmitageTest`），区组设计用 Page's L
  （`scipy.stats.page_trend_test`）。**Kruskal-Wallis 显著只说明「有组不同」，不是单调
  趋势的证据。** 用了打分就要写出你给各水平赋的分数。
- **计数与比例**：`chi2_contingency`（写明是否用了 Yates 校正）；任一期望频数小于 5 用
  `fisher_exact`，更有力的精确替代是 `barnard_exact` / `boschloo_exact`；比值比用
  `Table2x2(t).oddsratio_confint()`。**把 2×2 表本身报出来**，不要只给比值。
- **相关**：线性关系且近似二元正态用 Pearson，否则 Spearman；给 r 的区间
  （`pearsonr(x, y).confidence_interval()`）和 n。用聚合均值算出来的相关描述的不是个体
  层面的相关，要写明是哪一层的 r。

### 5.2 多重比较

先定假设族再看结果，**报出族的规模 m**。Holm 控制族错误率且不额外假设、一致地比
Bonferroni 更有力，读者期待 Bonferroni 时就优先给 Holm；Benjamini-Hochberg 控制 FDR，
适合假设很多的筛选。

```python
from statsmodels.stats.multitest import multipletests
multipletests(p, alpha=0.05, method="holm")   # 也接受 "bonferroni" "fdr_bh" "fdr_by"
```

**原始 p 与校正 p 放在同一张表的相邻列**，方法名和 m 写进表注。永远不要只给其中一个。

### 5.3 效应量与区间

**没有效应量的 p 值是半个结果。** 每个比较都要给效应量加区间：

- Cohen's d（合并 SD）或 Hedges' g（小样本校正）：
  `pingouin.compute_effsize(x, y, eftype="cohen")` / `"hedges"`。
- 秩检验给 Cliff's delta：`delta = 2U / (n1*n2) - 1`，等价于 `2*CLES - 1`。
- 二分类结局给比值比或风险比；关联给 r 本身。
- 抽样分布不标准时（中位数、比值、AUC 之差、Cliff's delta）用 bootstrap：
  `scipy.stats.bootstrap((x, y), statistic, n_resamples=9999, method="BCa",
  confidence_level=0.95, rng=...)`，配对数据加 `paired=True`。**报出重采样次数、用的方法
  （percentile / basic / BCa）和种子。**
- 「大／中／小」这种标签必须给阈值出处，并注明阈值依领域而定。

### 5.4 报告格式

- p 给两位有效数字（`p = 0.031`、`p = 0.0042`），只在低于 0.001 时写 `p < 0.001`。
  **绝不写 `p = 0.000`、`p = 0` 或不带数字的 `n.s.`**。单侧检验只允许在预先指定时使用，
  并写明。
- 检验统计量带自由度与样本量：`t(23.4) = 2.41`（Welch 自由度是小数，不要取整）、
  `F(2, 57) = 4.10`、`chi-square(3) = 8.2` 并给 N、`U = 412` 并给 n1 和 n2。用到大样本
  近似或连续性校正时说明。
- 每组的描述统计：参数检验给 n、mean (SD)，秩检验给 median [IQR]，另给缺失值条数与
  处理方式。一句完整的报告长这样：

> A 组高于 B 组（中位数 4.2 vs 3.1；Mann-Whitney U = 412，n = 24 与 26，p = 0.008；
> Cliff's delta = 0.41，95% BCa bootstrap CI 0.12–0.66；Holm 校正后 p = 0.024，
> m = 3）。

### 5.5 样本量与功效

样本量 n、效应量、显著性水平 α、功效 1−β 四件事锁在一起，固定其中三个第四个就定了。

- **效应量不许编。** 优先级：① 最小有意义效应（SESOI，会改变决策的最小效应）；② 预试验
  或前人估计，**但要收缩**（发表偏倚和赢家诅咒会把它抬高，直接用会功效不足）；③ 惯例
  （Cohen 的小/中/大），只在最后才用且要说明。**默认 α = 0.05（双侧）、power = 0.80**，
  确证性或临床研究常用 0.90；写下你用的值。
- 标准检验的闭式解：`sample_size(test="t_ind", effect_size=0.5, power=0.80, alpha=0.05)`；
  不等分配加 `ratio=`；固定 n 求最小可检测效应用 `mde(...)`；方差分析用
  `test="anova", k_groups=`；比例用 `test="two_proportions", prop1=, prop2=`。
- **没有公式的情形一律模拟**（logistic/Poisson 回归、混合模型、整群随机、生存、中介、
  交互）：按假定的真值生成数据 → 用你**真正打算用的那个检验**去分析 → 重复 ≥1000 次
  （要稳定到 80% 附近用 5000–10000 次）。功效 = 显著的比例，并报出 Monte Carlo 区间，
  否则读者分不清 0.81 和 0.79 是信号还是模拟噪声。
- 别忘的修正：多重比较（按校正后的 α，或直接用模拟跑受控流程）、脱落
  （`n_enroll = ceil(n_analyzed / (1 - dropout_rate))`，20% 脱落意味着多招 25%）、聚类
  （设计效应 `DEFF = 1 + (m - 1) * ICC`；把聚类数据当独立是伪重复，会严重高估功效）。
- **不要做事后功效（observed power）** —— 它是 p 值的确定性函数，不提供新信息，还是
  审稿人常见的扣分点。想知道「它能检测到多大」，就报固定 n 下的最小可检测效应，或直接
  给效应量的置信区间。
- **交付的不是一个数，是一段敏感性分析**：在一段合理的效应量范围内重算，画出功效曲线。
  单点数字掩盖了它最大的不确定性来源。

### 5.6 设计上不可挽回的错误

这些错误在分析阶段修不了，只能在设计阶段避免：

- **伪重复**：把同一个单位的重复测量当成独立重复。3 只小鼠各 100 个细胞，对施加在小鼠
  身上的处理来说 n = 3（小鼠），不是 300（细胞）。重复必须在处理被随机化的那一层；分析
  时用混合模型保留嵌套结构。
- **混淆**：处理组都在周一做、对照组都在周二做，就把处理和「天」混在一起了。能叫出名字
  的干扰因素（批次、天、板、操作人、仪器、孔位）都要随机化或区组化。
- **没有随机化或随机化被破坏**：靠「先来先入组」会让混淆溜进来。用带种子的分配表并照着
  执行（小样本用置换区组保证全程均衡；有预后因素用分层区组；干预在群体层面施加时必须
  整群随机）。
- **没有同期对照**，或该盲不盲；**板边缘效应**（蒸发与热梯度），不要把对照全放在第一列。
- **批次效应被当成生物学**：组学尤其如此，**绝不能让批次与条件对齐**。
- **忽略混杂结构**：低分辨率的分数析因设计会把主效应和交互混在一起，下「这个因子没
  影响」的结论之前先看 alias structure；**两级析因找不到内部最优**（检测不到曲率），
  要优化就用响应面设计。设计、种子和排程都要写下来存档（条件允许就预注册）。

## 六、图表与报告标准

### 6.1 图

- **按最终印刷尺寸作图**再 `width=\linewidth` 插入，不要画大了再缩 —— 15 英寸的画布塞进
  5.5 英寸栏宽，11 pt 刻度标签会变成 4 pt。栏宽：单栏 3.25 in、TEXT 5.5 in、WIDE 6.75 in；
  期刊宽度：Nature 89 / 183 mm，Science 55 / 175 mm，Cell 85 / 178 mm。
- **矢量出图**：`\includegraphics` 用 PDF，旁留一份 SVG 预览；PNG 只给真正的位图内容
  （照片、样本网格、像素级注意力图）。**折线图和统计图绝不用 JPEG。**
- **每一个数字都来自一次真实运行**，不许画记忆里的、四舍五入过的或「看起来合理」的数。
  **坐标轴必须带单位** ——「Loss」是标签，「step」不说明是优化步还是 token 就不算。
- **caption 就是标题**，图上不放 axes title。caption 首句用一句加粗的话点明结论，随后给
  读者信任它所需的方法事实：种子数、带/柱代表什么、平滑方式、归一化、哪些点被拟合、
  哪些被排除。约 28 词、常为三句。
- **画不确定性，或者明说没有。** 单个种子是轶事；跨种子画区间并写明种子数；只有一次运行
  就写「single seed」。
- **色盲安全、灰度安全**：用 Okabe-Ito 调色板 `['#E69F00', '#56B4E9', '#009E73',
  '#F0E442', '#0072B2', '#D55E00', '#CC79A7', '#000000']`。**绝不用 jet、rainbow、hsv**
  —— 它们会造出数据里没有的结构。连续量用 `viridis/plasma/cividis`，发散量用
  `RdBu_r/PuOr` 并把中心定在 0。基线与随机水平用灰色，颜色留给被比较的对象，并加一层
  冗余编码（线型、标记）。
- **多面板**：每个面板标 `(a)`、`(b)`（Nature 用小写，多数期刊用大写 A、B）；共享量的
  面板 `sharey=True`；整图一个图例；面板按论证顺序从左到右、从上到下；支撑不了同一个
  结论的面板应该是另一张图。分辨率：位图 300–600 DPI，线稿 600–1200 DPI 或直接矢量；
  字号（**最终尺寸下**）轴标签 7–9 pt、刻度 6–8 pt、面板标签 8–12 pt 加粗，全文一组
  无衬线字体（Arial/Helvetica），标签用句首大写并带单位。
- 交付前自查：轴都有单位；没有多余的图标题；不确定性画了且写了 n；被截断的序列图例里
  不留条目；脚本能从零重跑并复现出这张图；**打印尺寸下读一遍 PDF**。

### 6.2 报告标准

按研究类型选清单，逐条对照并在稿件里附完成版（带页码行号）：

| 清单 | 全称 | 适用 | 条目数 |
| --- | --- | --- | --- |
| CONSORT | 随机对照试验报告标准 | 任何 RCT（含预试验/可行性） | 25 条 + 受试者流程图 |
| SPIRIT | 干预性试验方案条目 | 试验方案 | 33 条 |
| STROBE | 观察性研究 | 队列、病例对照、横断面 | 22 条 |
| PRISMA | 系统综述与 meta 分析 | 系统综述（含不合并的） | 27 条 + 筛选流程图 |
| STARD | 诊断准确性 | 诊断准确性研究 | 30 条 + 流程图 |
| TRIPOD | 多变量预测模型 | 预测模型的开发/验证/更新 | 22 条 |
| ARRIVE | 体内动物实验 | 所有动物在体研究 | Essential 10 + Recommended Set |
| CARE | 病例报告 | 病例报告/系列 | 13 条 |
| SQUIRE | 质量改进研究 | 医疗质量改进 | 18 条 |
| CHEERS | 卫生经济学评价 | 经济学评价 | 28 条 |
| SRQR | 定性研究 | 定性/混合方法（替代：COREQ） | 按章节 |

**怎么用**：不是「照它写」，而是**逐条填，填的时候写清这一条落在第几页第几行**：

```
Item 7: 受试者纳入标准，以及数据采集的地点与环境
第 6 页 112–125 行："..."
```

然后在方法部分放一句符合声明：「本研究按 STROBE 声明报告，完成版清单见补充材料 1。」
一份稿件可能同时适用多份（带定性成分的预试验 RCT = CONSORT + SRQR；诊断试验的系统综述
= PRISMA + STARD）。审稿人最常见的拒稿原因里有三条是纯规范问题：**缺必需的清单；方法
细节不足以复现；该有的数据/代码可用性声明没写。**

机器学习和计算类投稿另有一张复现清单：数据集名称 + 版本 + 获取方式 + 预处理；**代码
可用性声明**；全部超参；随机种子；计算资源（例如
`Training used 4×A100 GPUs (~20 hours). Seeds: {42, 123, 456}.`）；统计显著性。

### 6.3 分析报告的最小骨架

一份能被别人接手、能过审的分析报告，段落顺序建议固定成下面这样：

```
# <把问题写成一句问句或一个可检验的主张>

**Answer.** 一句话：主数字 + 不确定度 + 方向。Confidence: high/medium/low，以及
最可能翻转它的那一个 caveat。

## 1. Question        → 原始措辞、约束条款（人群、时间窗、指标与单位、阈值、方向）
## 2. Data provenance → 上面的 provenance 表 + 行数流
## 3. Method          → 每个非默认参数和有影响的默认值，加上确切调用与软件版本
## 4. Results         → 主数字在前，带区间或 SD 和 n；原始与校正 p 并排；单位齐全
## 5. Checks performed→ 边界检查、换一条路径重算、换种子/换子集的敏感性、管线单测
## 6. Limitations     → 数据质量、未检验或被违反的假设、混淆、可推广的范围
## 7. Decision log    → 每个「别人可能选另一条路」的岔口：选了什么、备选是什么、
                       为什么、以及便宜的备选跑出来的结果
## 8. Reproducibility → 从原始输入重建每个数字和图的命令、环境、资源、产物路径
## 9. Interpretation  → 数字在前一节，主张在这一节，不要在结果里混进解释
```

三条硬规则：**结果与解释分开**；**决策日志要写**（审稿人最先读这一节）；**交付前做一致
性扫描** —— 正文里的数字 = 表里的数字 = 输出文件里的数字，引用的路径都存在，每条主张
都指向一个结果，没有占位符残留。

## 七、引用与来源审计

### 7.1 引用：先解析，再引用

**规则是绝对的：没有从一条活的记录里解析出来的条目，不许进参考文献；没有读过的文献，
不许用来支撑一个主张。** 语言模型会生成看起来非常合理的假文献，而审稿人现在会查。

- 每条记录现取现用：Crossref 取 DOI、OpenAlex 取作品、arXiv id、PMID。作者名、年份、
  标题、期刊、页码、DOI 全部从那条记录**抄**，不许回忆、不许凭印象补全。
- 标题检索：`works?query.bibliographic=<title>&rows=3`（Crossref）或
  `works?search=<title>&per-page=3`（OpenAlex）；只有标题高度一致**且**第一作者对得上
  才算命中。拿到 DOI 后取权威元数据，或 `https://doi.org/<doi>` 带
  `Accept: application/x-bibtex` 取一条现成条目再整理。
- 每条一个规范标识符：优先 DOI；没有 DOI 的预印本用 arXiv id；PMID 作为次要字段。已发表
  版和预印本都在时**优先引已发表版**；正文里用的数字来自预印本就说出来。一个主张只需要
  一两条能确立它的来源，不是五条提到这个话题的。
- 解析不出来的条目，**在报告里明说解析不出来**，不要把最佳猜测留在文件里。

**如果当前工作区不能联网**：不要凭记忆补全条目。把需要解析的条目标成 `unresolved` 并在
报告里列出，让用户在有网络的环境里补；把「未解析」当成一个正常的、要说出来的结果。

BibTeX 约定：条目类型用 `@article`、`@inproceedings`、`@misc`（预印本，带 `eprint`、
`archivePrefix = {arXiv}`、`primaryClass`）、`@book`、`@techreport`；只在需要保护大小写
的地方加花括号（`{BERT}`）；保留 `doi` 和 `url`，丢掉 `abstract` 和 `keywords`；引用 key
用 `第一作者年份关键词`，用过之后就固定；**外观交给期刊的 `.bst` 或 biblatex 样式，不要
手工排版**。

**审计已有的 `.bib`**：逐条问 DOI 能不能解析、解析出的标题/作者/年份/期刊名对不对得上，
每条标成 `verified`、`corrected`（写出修正）或 `unresolved`（保留条目并在报告里标出）；
同一篇论文在不同 key 下重复的合并到正文实际使用的那个 key。

**正文里的用法**：引用放在提出该主张的句子旁边，不是段末；区分「X 证明了」（他们的
结果）、「参见 X」（背景）、「沿用 X」（复用的方法）—— 措辞是署名的一部分；从来源抄来
的数字保留它原本的单位、精度和条件，做了换算就要说明。

### 7.2 来源审计：把每个主张钉到原文

来源审计回答一个问题：**这句话到底是从哪来的，那个地方真是这么说的吗？** 交付物是一张
表，不是一句「看起来没问题」。

1. **原子化**：把文本拆成小到能单独判真假的陈述。「X 在 Y 上把准确率提高了 4%，并且能
   泛化到 Z」是两条主张。
2. **先定位，再读**：找到确切的支撑段落（一句话、一个表格单元、一个图面板、一个数据
   字段、一次运行的指标），并在上下文里读它。**从「局限」段落里摘出来的句子，常常与
   建立在它之上的主张意思相反。**
3. **按措辞分级**（不按你的印象）：

| 等级 | 含义 |
| --- | --- |
| supported | 来源在**这个范围**内说的就是这件事 |
| partially | 来源说得更窄、更弱或有条件 |
| unsupported | 找不到来源，或来源根本没有涉及 |
| contradicted | 来源说的是相反的 |

   **回忆从来不是来源。** 数字必须逐字对齐：值、单位、精度、不确定度、条件。一个被四舍
   五入或换算过单位的数字，除非正文说明了换算，否则是 partially supported。**归属也是
   主张的一部分**：把一个正确的事实安到错误的论文上，是 contradicted。
4. **交付格式**：

```markdown
| # | 主张 | 等级 | 来源与位置 | 支撑原文 | 备注 |
| 1 | ... | supported | Smith 2023, Table 2 row 3 | "..." | |
| 2 | ... | partially | ..., §4.1 | "..." | 来源报 3.9%，正文写 4% |
| 3 | ... | unsupported | 未找到 | | 检索了 OpenAlex、arXiv |

Supported 14 · Partially 3 · Unsupported 2 · Contradicted 1
先修：#7（contradicted，核心主张）、#3、#9。
```

   支持与部分支持的条目必须有逐字原文和位置；不支持的条目要写清你找过哪里；摘要要点出
   「等级变化会改变全文结论」的那几条。**审计只报告，不修** —— 改文本是另一件事。

### 7.3 检索本身也要可复现

用于喂给下游分析或写成综述的检索，按四步走：① **先计数** —— API 暴露总数（`count`、
`total-results`、`meta.count`、`totalHits`）时先取总数；有些端点不给总数，那是一个要报告
的**已知状态**，不是可以编的总数。② **确定性地翻页** —— 按参考的分页方式
（offset/cursor/token）、按响应**实际报告的**页大小步进，永远不要假设页大小，尽量在稳定
排序下取。③ **对账** —— 报出期望总数 vs 实际取回总数、翻了几页、本地又过滤了什么。
④ **失败要可见** —— 翻页提前停了或计数对不上，在得出结论之前就说出来。

检索结果本身也要留 provenance：

```
## Retrieval Summary
- Query: <用户问的>       - Scope: 定向查询 | 穷尽式检索
- Databases queried: <端点与调用方式>     - Access date: <日期>
## Results
<条目：标题、作者、年份、期刊、DOI/PMID —— 用户真正需要的字段>
## Provenance
- Endpoints & parameters: <足以重放这次调用>
- Identifier conversions: <做过的话>
- Count reconciliation: <期望 vs 实际、翻了页数（穷尽式检索必填）>
- Warnings: <空结果、部分翻页、只有元数据没有全文、缺 key、端点已废弃>
```

**绝不要把元数据当成全文。** 拿不到全文时，诚实的报告是「这篇文章没有可用的全文，这是
摘要和可能找到开放获取副本的位置」，不是根据标题和作者列表写出来的摘要。

## 八、互查与自查

要评审别人的稿子或分析时：**读完整份东西**（含附录、补充表、代码）并且**要动手核** ——
输入在就重算一个数，给了分析就重跑一次，把图和它总结的表对一遍，检查检验和设计是否
匹配（配对还是独立、多重比较、数据是否不独立）。每个问题都要有定位（章节、页、表、图、
行）：「统计太弱」不是结论，「表 2 报告 p < 0.05，来自每条件 3 个种子的 t 检验，而 12 个
比较没有做任何校正」才是。分成 **BLOCKING**（核心主张不成立：信息泄漏、检验用错、基线
不公平、结果在数据里根本不存在、主张超出研究范围）与 **OBSERVATION**（能改进但不改变
「它对不对」），每条 blocking 给出**修复方案**；**结论从 blocking 列表推出来，不从个人
口味推出来** —— 没有问题的不因为「不够有趣」被拒，有一条 blocking 的也不因为写得漂亮
被收；作者已自己承认的局限不该被重复重罚。核不动的地方写成「未检查」，不能默认没问题。

### 8.1 审稿人最常抓的统计问题

按出现频率排：p 值被当成「假设为真的概率」、不显著被当成「没有效应」、显著被当成
「重要」；多重比较不校正、亚组钓鱼、**结局替换**；样本量不足与**事后功效**；只报 p 不报
效应量；相关当因果、生态学谬误、辛普森悖论；过拟合、外推到数据范围外、不看模型假设、
共线性掩盖效应；多组用 t 检验、非线性关系用 Pearson、期望频数太小的卡方、配对与独立
用错；置信区间被误读（「95% 概率真值在区间内」「区间重叠 = 无差异」）；连续变量硬二分、
反复试各种变换；默认整条删除缺失值而不看缺失机制；不做交叉验证与**数据泄漏**；**选择性
报告、把 p 四舍五入到 .05、不共享数据**。

## 九、打包归档

交付包要「**最小但自包含**」，并明确它是哪一种：存档级、可发表级、机器可读级，还是一次
轻量交接。包内必须保留：标题、范围、生成的文件清单与**不可变的产物版本**；代码修订号
**以及工作区是否 dirty**、数据标识符、许可与访问边界；环境与依赖规格、对硬件敏感的
设置、种子、配置；确切的重跑命令与期望输出；核对台账、失败或不确定的检查、局限、
provenance 链接；关键文件的校验和（可行时）。

流程：

1. 盘点候选文件，**排除**凭据、token、环境密钥、私有的绝对路径、缓存、临时断点、无关的
   大文件、隐藏的内核状态。
2. 清单里每一条都必须解析到一个真实存在的文件。只存在于 notebook 里的逻辑要么物化成
   可重跑的脚本，要么把「不可移植」这一点标出来。
3. 生成目标格式 + 一份简短的 README 或 manifest，包里的说法必须和来源与核对状态一致；
   每个输出独立验证：解析结构化文件、打开文档、检查压缩包成员、在安全时跑一次最小复现
   命令、比对校验和或关键计数；再扫一遍**像密钥的内容和机器相关路径**。**必需输入都不在
   的时候，不要把这个包标成「可复现」。** 复用已有的导出或发表路径，保留源文件，
   **未经明确许可不覆盖已存在的目标**。

终端状态只有一个，必须明说：`EXPORTED`（每个必需文件都在、都通过了校验，包满足声明的
契约）、`PARTIAL EXPORT`（有一个可用的包，但有具名的缺失或未验证组件）、`NOT EXPORTED`
（没有产出可信的包）。报告里要给：目标位置、清单、做过哪些验证、provenance 锚点、
**不可移植之处**；不要把失败或不确定的检查悄悄省略掉。

比较两个或多个产物时，先把判据冻住再算差异，并写一张「同基准」台账：数据/划分/预处理、
代码与环境与硬件、预算与停止规则与种子数、指标定义与方向与单位与聚合方式与不确定度
方法、缺失值与排除与失败运行。**有实质字段不匹配就把这次比较标成 confounded，不要把不
兼容归一化掉，也不要硬排一个名次。** 结论只能是 `WINNER: <target>`、`TIE`、`TRADEOFF`、
`INSUFFICIENT EVIDENCE` 四者之一；非胜出的结论都要给出下一个能区分它们的检查。

## 十、常见坑

| 现象 | 原因 | 怎么避免 |
| --- | --- | --- |
| 重跑同一个脚本结果对不上 | 没固定种子；线程数变了导致归约顺序变；dtype 推断跨块翻转 | 固定种子；导入前导出 `OMP/MKL/OPENBLAS/NUMEXPR` 线程数；显式 `dtype` |
| 跑了几小时，会话一断全没了 | 长任务挂在 shell 里 | 用受管作业提交并声明断点路径，入口先查断点状态 |
| CSV 读到一半列类型变了 / 读到的是半截的 | 某块出现了缺失值；写的时候没走原子替换 | 显式 `dtype` 并分块读取；临时文件 + `fsync` + `os.replace` |
| 「跑通了」但数字是错的 | 中间某步静默失败 | `set -euo pipefail`，每条命令记 exit code |
| 论文里的数字和输出文件对不上 | 手抄的 | 交付前做一致性扫描：正文 = 表 = 文件 |
| 复现时发现作者代码跑不起来 / 结果「差不多」但不是 | 论文只给了方法描述；跑完才定容差 | 先找原作者发布的代码/配置/权重；容差在运行前写进 target 记录 |
| 声称预注册但拿不出一份事前清单 | 事后补了校验和 | 校验和只证明一致性；预注册要运行前写下的设计清单 |
| 引了一条查无此文的参考文献 | 凭记忆生成 | 每条都从活记录解析；解析不了就标 unresolved |
| 被引用的事实其实是原论文的反面 | 从「局限」段摘的 | 逐字读上下文并抄下支撑原文 |
| 图打印出来字看不清 / 色盲读者分不清两条线 | 先画大再缩放；用了 rainbow/jet 或只靠颜色 | 按最终栏宽作图并在打印尺寸下看 PDF；Okabe-Ito + 线型/标记冗余编码 |
| 论文被拒在格式上 | 缺清单、方法不够复现、没有数据/代码可用性声明 | 投稿前逐条填报告清单；补可用性声明 |
| p 值一堆但看不出大小 / 一个分析跑出好几个「显著」 | 只报了 p；没校正多重比较 | 每个比较都给效应量 + 置信区间 + n；先定假设族、报 m、原始与校正 p 并排 |
| 强结论压在一只小鼠的 300 个细胞上 | 伪重复 | 在处理被随机化的那一层重复；混合模型保留嵌套 |
| 交付包里带出了密钥或本机路径 | 没做最后一遍扫描 | 打包最后一步扫密钥与机器相关路径；不完整就标 PARTIAL |
| 数据/代码只在本地，别人拿不到 | 没给标识符或访问方式 | 给出存档标识符与获取脚本；大数据集不塞进包 |

## 十一、交付物清单

一次完整的产出，应该同时有下面这些东西（按需裁剪，但裁剪要说明）：

- [ ] **目标/设计记录**：`reproduction/<name>/target.md` 或事前设计清单，写于运行之前。
- [ ] **原始数据保持只读**，清洗与派生数据由编号脚本生成，可重跑；脚本参数 `--in`、
      `--out`、`--seed` 明确；**环境锁定**（`requirements.lock` 或等价物）与关键版本号。
- [ ] **run.log**：每条贡献数字的命令 + exit code + 耗时。
- [ ] **provenance 表**：来源、版本、访问日期、行数进出、过滤、校验和。
- [ ] **结果文件** `results/*.csv`，含 n、效应量、区间、原始与校正 p。
- [ ] **图 + 生成它的脚本**成对存放，caption 写好，轴带单位，不确定性有 n。
- [ ] **分析报告**（6.3 骨架），含决策日志与 Checks performed。
- [ ] **完整的参考文献列表**：每条都解析过并有 DOI/arXiv id，无 unresolved 残留（有的话
      列出来）。
- [ ] **来源审计表**（主张级），支持与部分支持的行带逐字原文与位置。
- [ ] **适用的报告清单**完成版，带页码行号。
- [ ] **打包件**：manifest/README、重跑命令、校验和、许可与访问边界，状态是 `EXPORTED`
      或如实标注的 `PARTIAL EXPORT`。
